# Agent Note: 桌面打包与迁移文件安全

Status: proposed

[English](2026-09-27-wanwei-upgrade-files.md) | 中文

## 问题

运行时打包使用递归删除处理依赖链接，不适用于 Windows junction。旧数据迁移直接写入最终文件，中断可能留下不完整文件，后续迁移会把它当作已存在而跳过。

## 提案

打包链接使用解除链接操作，只有普通条目才递归删除。旧文件先复制到同目录独占创建的临时文件，同步字节后通过不覆盖目标的硬链接发布。保留已有目标文件，正常成功或失败后删除临时名称。

## 考虑过的替代方案

**重命名临时文件。** Unix 重命名可能替换已有目标，违反不覆盖要求。

**独占创建后直接写入。** 可避免替换，但进程中断仍会留下不完整的正式文件。

## 验收标准

真实 Windows junction 测试保留源依赖包。迁移测试保留已有数据、发布完整新数据并清理失败的临时副本。macOS/Linux 文件系统及安装升级仍需单独验收。

## 风险

应用数据所在文件系统必须支持硬链接。不支持时迁移失败且不会记录完成标记。强制终止迁移可能留下临时文件，但不会以最终名称暴露不完整文件。这也不保证正在变化的旧 SQLite 数据库具有一致快照。
