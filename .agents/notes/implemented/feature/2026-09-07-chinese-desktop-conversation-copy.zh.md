# Agent Note：桌面端对话中文优先文案

状态：已实施

[English](2026-09-07-chinese-desktop-conversation-copy.md) | 中文

## 问题

桌面端主要面向中文用户，但对话流程仍混有中文回复、英文斜杠命令说明、工具行操作和技术界面标签。无浏览器信号的启动路径也会打开英文，与产品语言不一致。

## 决策

桌面端对话文案采用中文优先策略。浏览器和 Host 显式偏好都未选择已提供语言时，以 `zh` 作为打开语言；`en` 仍作为缺失翻译的词典回退。工具行、技能行、输入/输出标签、查看详情操作，以及内置 `/goal`、`/permission`、`/plan`、`/model` 的说明使用中文业务动作；当 `Bash`、`Pwsh`、命令名、路径和字段代码有助于识别操作时，保留这些技术标识。桌面模型指令要求使用简洁中文输出可见进度和结论，且不展示内部推理或英文内心独白。

原始服务错误、命令和工具标识、文件路径、API 名称、Shell 语法、包名和数据字段代码保持原样。客户端不会在展示前翻译错误载荷。

本决策替代[全量客户端本地化](../architecture/2026-07-30-client-locale-full-rollout.md)中关于工具标题和打开语言的部分；其类型化本地化机制及其他非翻译边界继续有效。

## 备选方案

- **翻译全部技术标记**——不采用。改写命令、路径、字段代码或原始错误会降低排障能力，并使复制后的指令不可靠。
- **保留英文打开语言，仅翻译模型回复**——不采用。原生和无浏览器路径仍会展示英文客户端界面。
- **在渲染器中翻译服务端错误**——不采用。原始诊断信息必须可搜索和审计。

## 影响

中文桌面会话会呈现一致、以操作为中心的对话界面，同时保留运行和支持所需的技术术语。用户仍可通过显式语言偏好或英文浏览器使用英文。新增面向对话的界面文案必须使用类型化本地化入口，并遵循中文业务语言与原样技术材料的划分。

## 验证

定向语言、命令、工具行和技能行测试覆盖中文默认语言、英文回退、本地化的已知命令元数据，以及保留技术标识的中文工具和技能操作。契约类型检查覆盖跨包本地化键。
