# Agent Note: Separate skill downloads from distinct installations

Status: implemented

[English](2026-10-10-skill-download-installation-counts.md) | 中文

## Problem

桌面热门下载量和管理员安装量描述不同的数量。未携带登录凭证的安装上报被 OneAPI 拒绝，静默失败又隐藏了计数缺失。

## Decision

桌面使用 Host 保存的登录令牌和新下载事件 ID 确认完整技能包接收，再用该 ID 确认原生安装成功。OneAPI 在事务中插入去重事件、递增原有下载总量并更新账户与技能汇总。安装确认只更新汇总中的曾安装标记，并保留原有去重安装记录，不增加下载量。卸载不扣减任何计数。调用统计和 SkillHub 下载量保持不变。

`skill_user_stats` 使用 `(user_id, skill_id)` 复合主键，保存累计下载量、曾安装布尔值、首次及最近下载和安装时间、最近安装版本。`skill_download_events` 使用 `(user_id, event_id)` 复合主键，保存稳定技能 ID、下载版本、下载时间和可为空的安装确认时间。重复上报不递增计数；同一事件不能改指其他技能或版本。新增技能和用户不需要改表。软删除保留历史。不新增用户明细管理页面。

启动时从 `skill_installations` 回填已知首次安装，不覆盖已有汇总，也不编造历史用户下载次数。现有技能总下载量保持不变。旧客户端沿用合并安装上报，每条收到的上报计一次下载及安装确认；旧协议无法提供重试去重 ID 或下载版本。

## Alternatives considered

**共用一个计数器：** 按用户去重会隐藏桌面重复下载，累计计数则会夸大管理员列表中的独立安装人数。

**从历史总量推测身份：** 历史下载没有账户身份，回填去重人数会编造数据。

## Consequences

独立的下载接收及安装确认需要同时更新 OneAPI 和桌面端。下载确认失败会停止本地安装；安装上报失败会保留已完成的本地安装并显示同步失败提示。上报不会自动重试或在重启后补报，因此统计反映服务器已接受的确认，而非每次文件系统操作。事务保证事件和计数一起回滚。模型测试覆盖去重、多用户、版本、回滚和可重复执行的历史回填；通过 Loader 加载的 Host 测试覆盖带认证的两阶段请求顺序。安装包实测及生产数据库类型验证仍属于部署验收。
