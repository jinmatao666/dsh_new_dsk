# Agent Note：后台运行时部署路径

Status: implemented

[English](2026-10-30-runtime-backend-deployment.md) | 中文

## Problem

构建期公开 URL 使相同后台版本依赖具体现场网络。变更前缀还会影响按需脚本、图标、认证跳转及桌面端安装包地址。

## Decision

后台在连接数据库前校验公开配置，并在禁止缓存的 HTML 中注入公开设置和 base 元素；不可变脚本据此选择 Webpack 资源路径、路由前缀和接口地址。服务端进入 Gin 路由前去除已配置前缀。规范接口 URL 保留完整路径，管理端认证回调使用单独解析的管理地址，第三方完整 URL 保持原样。

独立交付入口将现场配置和持久化数据保留在镜像外，在无网络条件下检查本地带版本的镜像，升级只改变程序镜像标识。企业管理端保留独立端口，特定服务器和专家检查不参与通用交付。[操作说明](../../../../services/one-api/deploy/README.zh.md)统一维护部署细节。

## Alternatives considered

**针对客户单独构建前端。** 增加产物数量，互联网验证通过的镜像无法直接用于离线交付。

**Nginx 替换打包脚本。** 哈希和压缩产物及按需加载会让部署正确性依赖每次构建的实现细节。

**用转发头推断规范 URL。** 多层代理可能覆盖协议、域名或前缀，显式完整地址消除这种歧义，客户端 IP 转发信任由独立白名单控制。

## Consequences

现场通过重建容器改变路径，网关保留前缀，完整 URL 路径与运行配置必须一致。初始化不覆盖现场配置，程序回退保留数据库但不能撤销迁移。CPU 架构作为镜像发布维度，不形成客户专用分支。

## Testing

Go 与 React 定向测试覆盖校验、路由、跳转及 URL 生成；嵌入的生产资源检查和本地浏览器 smoke 使用同一份前端构建及 mock 接口覆盖根路径和两组前缀。交付工具测试隔离 Docker 调用，验证配置保留及架构不符时拒绝执行。按用户要求暂缓 Docker 镜像构建、真实桌面与模型流量、正式代理及数据库恢复验收，本地检查不代表这些流程已通过。
