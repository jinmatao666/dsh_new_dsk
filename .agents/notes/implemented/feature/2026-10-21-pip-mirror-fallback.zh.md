# Agent Note: 桌面 pip 命令的顺序镜像回退

Status: implemented

[English](2026-10-21-pip-mirror-fallback.md) | 中文

## 问题

中转服务器可以快速访问国内 PyPI 镜像，但官方 PyPI 下载会超时。pip 的多个索引不能表达按顺序回退的策略，由模型驱动的重试也容易混淆哪些尝试真正成功。

## 决策

OneAPI 插件默认配置按华为云、清华、官方 PyPI 的顺序提供索引。内网中转模式通过私有 Python 模块覆盖层委托已有 pip 导入，并以独立子进程管理使用默认索引的 `python -m pip download/install`。每个源仅尝试一次，完整限时 30 秒。网络和包版本不可用诊断允许回退；本地权限、参数、构建和完整性失败不允许回退。封装保留已配置的代理环境，不会为了恢复下载而切回直连网络。显式索引或代理选择及本地安装保持原行为。

覆盖层仅作用于 sidecar 环境，卸载时移除，离线资源和外网模式下禁用。成功标记避免之前失败的尝试触发最终依赖失败提示。本实现不包含后台配置界面。

## 考虑过的替代方案

**附加索引：** pip 会综合各个索引中的候选包，而不是实现所需的主备顺序，无法保留时延控制。

**全局 pip 配置或修改安装：** 这些方式影响无关的 Python 应用，且在桌面网络策略切换后仍然存在。进程级覆盖层保留已有安装。

**模型自行换源：** 这依赖模型遵守指引，也可能在没有固定预算时重复失败命令。封装为受支持的入口强制执行尝试顺序和退出状态。

## 影响

默认路由仅在两个国内镜像均失败时使用较慢的官方 PyPI。控制台 `pip` 启动器、隔离解释器和覆盖模块路径的命令不获得自动回退。安装失败可能留下 pip 管理的副作用，重试不提供事务回滚。源码归档和平台特定构建要求仍由 pip 负责。尝试超时时会终止原生 Windows 进程树或 POSIX 进程组。

## 验证

真实 Python 子进程测试覆盖主源成功、顺序回退、全部源失败、超时、终止性失败、显式源和本地安装透传、已有 pip 委托、模式切换及覆盖层清理。Loader 组合工具测试验证路由激活和恢复成功后的结果反馈。客户服务器及打包 macOS/Linux 验收仍需外部检查。
