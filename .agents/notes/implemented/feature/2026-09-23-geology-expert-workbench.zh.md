# Agent Note: 地质条件分析专家工作台

Status: implemented

[English](2026-09-23-geology-expert-workbench.md) | 中文

## Problem

聊天形式的技能可以完成地质分析，但偏好引导式专家页面的用户需要材料上传、任务历史和报告入口，同时不希望普通会话列表多出记录。管理员也需要在不修改执行代码的情况下控制专家是否展示。

## Decision

OneAPI 的专家名单只包含桌面端已经实现的工作台。管理员编辑展示资料和上架状态；可选的关联技能仅作说明，不改变执行。地质条件分析、三调土地利用现状分析和土地利用规划审查在桌面端分别使用固定的材料、历史和结果组件。执行前如有需要，各工作台会安装其固定技能：`market-gis-geology-analysis`、`market-gis-third-survey-analysis` 或 `market-gis-land-use-plan-review`。每次运行建立独立目录和归档的 Host 会话，只调用该专家自己的技能，并展示该会话的回答、分析视图数据以及实际生成的 Word、Excel 文件。每个专家使用独立的按用户划分的本机任务索引。

工作台依据归档会话和文件呈现运行中、已完成、未完成状态。历史页读取各任务结果；成果页只列出该任务实际返回的文件。执行链路没有提供可核实的地图、数值统计、进度百分比和阶段日志，因此页面不展示这些数据。

## Alternatives considered

**通过管理端上传任意工作台网页。** 每个工作台都需要经过检查的输入、执行和结果代码；任意上传会使已上架卡片无法保证存在可用的分析流程。

**由管理端的关联技能字段决定执行。** 资料编辑可能无意改变任务流程或跳过必要的预处理，因此执行技能固定在已发布的工作台代码中。

**为专家任务创建普通聊天会话。** 用户完全在专家页面操作时，普通会话列表会增加多余记录。归档会话保留 Host 的技能与模型调用链，同时不占用普通会话列表。

## Consequences

服务器可在不发布桌面新版的情况下调整上架状态和卡片文案，但新增工作台仍需桌面端实现。本机历史不跨设备同步，且依赖任务目录和 Host 会话仍可访问。只有实际存在两种成果文件才会标记完成；模型回答本身不足以构成成功。三调和规划审查工作台复用地质专家的交互结构，但技能参数、任务目录、会话、历史、结果和上架条目彼此独立。

## 办公文件专家扩展

文件转换与 PDF 工具专家在工作台中固定调用五个正式技能：Word 转 PDF、PDF 转图片、PDF 合并拆分、图片转 PDF 和图片优化。文档智能处理专家独立固定调用文档摘要与文档对比技能。两者复用少量任务外壳，用于文件导入、归档会话、真实状态判断、本机历史和成果打开，同时保持任务索引、目录、顶部标签、服务端名单条目和技能选择彼此独立。上传原件不会计入成果；批量任务是否完成还取决于实际生成文件数量。正式素材补充前，文档智能专家使用可由后台集中替换的展示图标字段。
