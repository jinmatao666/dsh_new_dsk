# Agent Note: 自动化结果推送

Status: implemented

[English](2026-10-29-automation-result-delivery.md) | 中文

## 问题

选择连接器工具不能保证定时任务结束后交付结果。用户需要持久化的推送开关，无需每条提示词额外要求发送。

## 决策

任务保存可选的 `pushChannels`，默认关闭。编辑器以权限右侧下拉菜单中的独立推送开关替代连接器选择。未连接时在保留草稿的编辑器上打开原有授权弹窗。Host 结束执行记录后保存最终文字和各渠道推送状态，再直接发送，不额外请求模型。推送失败不影响任务状态，重试只处理失败渠道，不重跑任务。CLI 推送按运行和分段使用稳定幂等键；微信接口没有幂等键，发送结果不确定时重试可能重复收到消息。

此决策部分替代[飞书连接器与自动化](2026-10-24-feishu-connector-automation.zh.md)中的自动化工具选择。原记录继续描述独立的 CLI 授权、技能和双向会话机制。旧选择不自动授权对外推送。

## 考虑过的替代方案

**只靠提示词发送。** 模型遗漏、工具权限和业务失败使结果交付不确定，因此拒绝。

**发送失败后重跑任务。** 会重复任务的副作用，因此拒绝。

## 影响

飞书以机器人身份发送给已授权本人；钉钉通过稳定 ID 查询本人后使用个人授权发送；微信要求有效的本人入站回复会话。结果分段按序发送有界文字，产物列出桌面路径，暂不上传附件。中断的待推送记录标记失败供明确重试。本机调度仍要求桌面端运行。

## 验证

定向测试通过真实 Loader 和 Session 执行配合模拟推送服务，覆盖独立失败与重试、开关默认关闭、授权保留草稿、接收人解析和长文本分段。
