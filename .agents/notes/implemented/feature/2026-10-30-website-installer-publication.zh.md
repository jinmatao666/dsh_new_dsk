# Agent Note: 官网安装包独立发布

Status: implemented

[English](2026-10-30-website-installer-publication.md) | 中文

## Problem

首次访问的用户需要 EXE 或 DMG 安装包。签名桌面更新 ZIP 服务于已安装客户端，不能用于相同的下载流程。官网独立于后台镜像部署。

## Decision

OneAPI 管理三个安装目标，每次上传独立且不可变，每个目标有独立的发布指针。系统超级管理员通过版本发布页面上传、发布、撤下和删除。公开目录和下载接口只公开当前选中且已发布的文件，撤下不会回退到历史版本。

文件复用更新包的持久化父目录，存放在独立的 `website-installers` 子目录。数据库记录、发布控制和文件校验与签名更新保持独立。公开目录允许不携带凭据的跨域读取，供独立官网调用；后台镜像仅包含其管理界面。

## Alternatives considered

**复用签名更新产物。** 这会混用首次安装格式与 Tauri 更新签名、发布状态，不符合独立发布控制的需求。

**将官网打包进后台镜像。** 用户要求独立部署，公开目录可以完成对接而无需打包官网资源。

**使用另一处持久化挂载。** 在已有更新包挂载下增加子目录，可以保留部署和备份配置，并分开存储文件。

## Consequences

后台提供稳定目录，发布时校验存储文件哈希。管理员仍需核实应用版本、DMG 架构、系统签名和实际安装结果。独立官网还需要调用该目录。数据库和文件存储均需备份，详见[操作说明](../../../../services/one-api/docs/website-installers.md)。

## Testing

控制器及路由测试覆盖鉴权、文件持久化、三个目标、无效格式、大小限制、篡改、替换、撤下、删除及 GET/HEAD/范围下载。React 测试覆盖上传参数、重试、切换目标、操作确认和服务端状态同步。这些检查不验证生产代理行为或实际安装包的有效性。
