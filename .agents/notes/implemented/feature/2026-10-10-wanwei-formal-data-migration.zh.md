# Agent Note: 万维Buddy正式身份与历史数据迁移

Status: implemented

[English](2026-10-10-wanwei-formal-data-migration.md) | 中文

## 问题

多数用户使用数据位于 `~/.dsh` 的原始桌面端，少数用户使用独立安装的新一代客户端。只恢复显示名称或复制一处目录会让另一类用户无法访问历史记录。只复制存储文件、不合并工作区记录，会隐藏已导入的会话。

## 决策

桌面端显示名称为万维Buddy，可执行文件为 `wanwei-buddy`，正式应用标识为 `com.wanwei.harness`。开发版使用 `com.wanwei.harness.development`，不参与历史迁移。安装包、启动壳和 GitHub 发布使用一致的产品名称。工作流文件名保持稳定，兼容现有触发调用。

原生迁移模块在正式 Sidecar 启动前执行一次性导入。按优先级识别正式目录、`com.wanwei.harness.preview/dsh-home` 和 `~/.dsh`，为设置、身份、会话、存储、附件、技能及兼容预设保留来源副本，原目录不动，并准备完整的暂存目录。历史可执行 Profile 补丁与登录凭据不启用，现有正式运行配置保留。工作区注册表 v2 按文件系统路径合并；ID 冲突但路径不同的工作区分别保留，会话成员取并集。工作区绝对路径不变。

相同会话文件去重；字节前缀一致的续写日志保留较长文件，不合并事件。分叉日志和不同编码保留优先版本作为当前会话，所有来源版本均保存在 `migration-backups` 中，冲突路径列入 `.wanwei-formal-migration-v2.json`。冲突的已安装技能保持完整，不混合脚本与密钥。分叉版本不会自动显示成两条会话，不支持的会话事件与缺失的外部文件不转换或重建。

复制与索引校验完成后，完整暂存目录才替换使用目录。正式目录原数据移入恢复目录而非删除；待发布记录支持中断恢复。索引不兼容或复制失败会停止启动，不静默启动为缺失历史的状态。升级前必须关闭两个历史应用；快照复制不能与另一应用的实时写入形成事务。

## 考虑过的替代方案

**只改显示名称。** 仍保留独立安装身份，无法统一安装或导入原版用户记录。

**用一个目录覆盖另一个。** 会丢失独有记录与配置，并混合不同技能版本。暂存、来源副本与理解索引结构的合并保留恢复能力。

**拼接分叉日志。** 不同事件序列可能包含不兼容的工具与分支引用。保留优先使用日志及全部来源版本，避免生成虚构的会话；自动分支转换不属于此次导入。

## 影响

多数用户可直接从原产品升级，不需要安装中间的独立版本。迁移额外占用磁盘，因为原目录与来源副本保留。Rust 测试覆盖单一来源、双来源、工作区合并与 ID 冲突、续写与分叉日志、索引拒绝及中断发布。Windows/macOS/Linux 安装升级与实际历史记录验收仍属平台检查，临时目录测试不能证明实机兼容。
