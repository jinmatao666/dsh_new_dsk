# Agent Note：资源扣分点

Status: implemented

[English](2026-11-16-expert-charge-points.md) | 中文

## 问题

三类资源需要由后台统一定价，不再让各服务自行传入金额或采用不同协议；新增技能应自动获得默认计费关联。

## 决定

知识库服务整体扣分点在同一套查价、预留、结算和管理路径使用 `kind=knowledge_service`、固定 `item_id=default`，不依赖占位知识库。当前平台用户从本人账户支付，专家限定凭据不能访问此范围。知识库业务维护服务权益并选择收费时机；Go 传输封装支持具体库及服务级范围，不自动给已有业务处理函数增加收费。规则类型字段支持服务级标识长度。

专家、技能和知识库共用后台定价 HTTP 接口以及同一规则和任务存储。业务类型、资源标识和固定扣分点 ID 标识价格。专家复用已有服务端身份兑换；技能携带当前账户；知识库将当前请求的登录头转发到本机 HTTP 接口。不接受任意付款用户 ID。移除业务自传金额入口和 Python SDK。

新增技能在事务内创建默认点，启动时按历史价格初始化已有技能；资源和动作的唯一约束处理并发。技能执行器动态查询默认 ID，其他收费节点由业务配置对应 ID。独立积分弹窗避免在技能内容编辑中重复定价。知识库管理页面和具体收费节点由知识库同事后续实现。

停用扣分点按零费用执行。关闭平台积分时明确返回免计费，不依赖价格配置；调用方继续业务并跳过结算。已预留任务保留金额和名称快照。失败取消释放，业务成功但结算不确定时只查询或重试原结果，不新建收费。无名称快照的历史任务沿用原展示。

## 考虑的替代方案

各服务传金额会绕过后台统一定价；多套 SDK 会形成不同接入说明，因此 HTTP 文档为统一依据。Go 知识库辅助代码只负责转发 HTTP。回环调用有超时限制，仅将用户凭据转发到本机配置端口并拒绝跳转。知识库原有资源权限仍由现有逻辑校验；准备接入对象不自动收费，也不改变 RAGFlow 计费。

## 影响

删除扣分点会从管理列表隐藏，并原子写入停用、零价格的内部记录，保留原 ID 与资源归属。已接入的调用继续免费执行；未知或跨资源 ID 仍报错。技能初始化不会重建已删除默认点。版本校验防止过期编辑或删除覆盖当前配置、重新启用已删除点；已有任务按原快照结算。

停用积分或扣分点不能阻止业务。知识库同事仍需实现具体收费节点并保留现有资源权限校验。本次不增加长任务续期或任务凭据找回。

## 验证

控制器测试覆盖三种资源、技能默认 ID 稳定性、名称和价格快照、停用免费、总开关免计费、原价结算及结果幂等。专家兑换测试覆盖凭据归属、撤销和过期。知识库传输测试验证认证后的查价、预留和结果 HTTP 调用。技能执行器测试覆盖动态查点、免计费、余额不足及原有触发机制。管理页面测试验证独立弹窗与技能删除前的积分入口。专家真实收费节点和知识库后续策略仍需部署联调。
