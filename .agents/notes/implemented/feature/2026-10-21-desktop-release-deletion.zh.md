# Agent Note: 桌面发布记录删除保留版本历史

Status: implemented

[English](2026-10-21-desktop-release-deletion.md) | 中文

## 问题

管理员需要删除不再使用的桌面更新包，同时不能破坏当前更新通道或清除其降级保护。

## 决策

受超级管理员鉴权保护的删除接口仅接受未发布记录。[控制器](../../../../services/one-api/controller/desktop_update.go) 按与发布相同的顺序锁定更新记录及平台通道。删除已撤下的当前记录时清除通道引用，但保留历史最高版本。数据库删除先提交，再清理文件；清理失败时报告警告并记录残留文件供运维处理，不恢复为可发布记录。

管理员须确认永久删除。列表操作保留当前页，末页删空时回到有效页。更新说明使用居中且受视口约束的弹窗，长文本可滚动。

上传及列表筛选复用后台自定义下拉组件，不使用操作系统原生菜单。禁用的架构选项仍不可选，保留键盘导航、Escape 关闭及可见焦点。样式仅作用于发布页面控件，其他后台页面外观不变。

仅当历史版本对应的平台／版本上传记录仍存在时，发布低于该历史版本的更新才须提供绑定候选版本的额外确认，详见[已删除版本警告决策](../bug-fix/2026-10-22-deleted-release-publication-warning.zh.md)。管理员看到确认提示而不是错误通知。客户端更新可用性将选中记录的实际版本与请求客户端版本比较。因此发布旧记录不会向较新客户端提供降级更新，且仍须验证签名。

## 考虑过的替代方案

**直接删除正在发布的版本。** 客户端发现更新期间可能失去对应文件。先显式撤下可将可用性变更与永久清理分开。

**随记录一起删除平台通道。** 这会丢失独立的发布状态。记录删除后仍保留通道，但已删除上传记录不参与低版本确认。

## 影响

删除移除选中记录，并尝试仅清理以其标识命名的文件目录，不卸载客户端软件。文件系统与数据库变更并非原子操作。集成测试覆盖鉴权、拒绝删除发布中版本、草稿及撤下记录删除、缺失标识、文件清理和降级保护。前端测试覆盖确认、错误及分页；生产页面检查覆盖 1440、820 和 390 像素的弹窗边界。生产环境实际删除仍由运维验收。
