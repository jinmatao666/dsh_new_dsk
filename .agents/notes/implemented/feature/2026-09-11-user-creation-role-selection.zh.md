# Agent Note: 创建用户时选择角色

Status: implemented

[English](2026-09-11-user-creation-role-selection.md) | 中文

## Problem

管理员需要在创建用户时明确指定业务角色，而不是依赖隐式默认值。

## Decision

后台创建和编辑用户表单从角色管理接口读取已启用角色。

所选角色编号直接写入 `users.role`。

服务端只接受角色管理表中存在且已启用的角色；既有调用方遗漏角色时仍按普通用户处理。

10 及以上编号继续保留给既有系统管理判断；自定义角色使用 2 至 9 的编号。

角色明确配置的模型列表与用户分组可见模型取交集。服务端将该交集同时用于桌面端模型详情发现和 OpenAI 兼容模型列表，并拒绝角色列表以外的模型请求，即使客户端仍保留过期的本地配置也不能调用。

桌面端窗口重新获得焦点时会刷新服务端管理的模型提供商，保持打开期间每五分钟也会刷新一次。临时刷新失败保留已认证的模型提供商；认证失败仍会退出登录。

## Alternatives considered

保留固定的普通用户和超级管理员两项选择。

用户表单将无法反映通过角色管理新建的角色。

仅依赖浏览器隐藏超级管理员选项。

构造请求可以绕过浏览器，因此服务端必须执行相同限制。

只过滤后台模型选择界面。

桌面端模型发现和直接 API 请求仍可能展示或调用角色列表以外的模型，因此每条认证模型路径都由服务端执行交集过滤。

## Consequences

新建和编辑账号获得角色管理表中存在的明确角色。

既有数字化系统管理判断保持不变，角色权限可分别定义每个角色的模型访问权限。

角色模型调整会在桌面端重新获得焦点或定时刷新时同步，服务端请求限制则立即生效。
