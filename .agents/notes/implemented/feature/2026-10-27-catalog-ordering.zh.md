# Agent Note：技能和专家目录统一排序

Status: implemented

[English](2026-10-27-catalog-ordering.md) | 中文

## 问题

后台列表与桌面目录使用不同的排序规则，管理员还需要记录技能和专家是否依赖互联网。

## 决策

技能、独立专家网站及两种分类表保存可空整数 `sort_order`。填写数字的条目优先，数字从大到小；相同数字或未填写数字时按创建时间倒序，再按主键确定顺序。拖动或上下移动会在事务中将服务器完整有效列表归一化为递减序号。客户端提交来源和目标标识，不根据筛选后的页面自行计算序号。桌面技能列表默认保留服务器顺序，仍允许用户选择热门下载或最近更新。专家分类位置随专家元数据传递，与卡片自身顺序独立。

技能和独立专家网站保存 `requires_internet`，数据库默认值为 true。缺列升级使已有记录初始化为 true，后续迁移保留 false。历史专家未记录真实创建时间，因此使用原更新时间补齐。联网标记同时控制内网目录展示：既有终端联网判断未确认可访问时，`internetCatalogPolicy` 指定隐藏或灰化，默认灰化。不需要联网的条目保持可用；网络刷新确认恢复后重新显示或启用，需要联网的已运行工作台不被中断。处理范围仅限目录交互，不改变资源路由、自动化或连接器策略。

## 考虑过的替代方案

只在客户端排序会使各安装实例顺序不同。只交换两个可空序号无法处理相同序号或空值。每次启动统一将联网标记刷成 true 会覆盖管理员选择。

## 影响

移动操作为完整有效列表分配明确序号，包括当前分页以外的条目。清空序号后，该条目排在已填写序号的条目后面，参与创建时间排序。分类类型和分类关联自身的历史排序保持独立含义。模型请求、专家凭据和下载统计不变。

## 验证

数据库测试覆盖历史缺列迁移、保存 false 后重复迁移、零值及负数序号、空序号、完整列表移动、无效目标、分类关联查询和 PostgreSQL DISTINCT 排序。桌面与后台测试覆盖默认顺序、元数据投影、按钮与拖动请求及可空字段。TypeScript 检查覆盖宿主端与客户端。
