# Agent Note: 按网络环境控制功能入口

Status: implemented

[English](2026-10-10-environment-feature-visibility.md) | 中文

## 问题

管理员需要分别控制互联网和纯内网部署的自动化、连接器入口。全局开关或固定的纯内网禁用规则无法表达仅内网开放连接器的部署方式。

## 决策

系统设置在 SystemDeploymentSettings.features 中保存按环境及入口区分的四个独立布尔值。缺少 features 的现有记录默认两种环境均开启自动化、仅互联网开启连接器。显式配置不完整或非布尔值时拒绝接受。公开 desktop-config 响应只包含允许公开的两种环境行，不包含私有配置。

认证插件在启动及登录刷新时读取配置。独立业务插件各自向 feature-panels 提供入口可见性观察对象。隐藏入口不渲染占位，并关闭已打开的对应页面。现有侧栏保持设置位于底部，其余菜单向下补位，无需修改 CSS。开启内网连接器不会解除外发网络限制，也不会创建真实连接器集成。

## 考虑过的替代方案

**两种环境共用开关：** 无法满足内网开启、互联网关闭的需求，因此不采用。

**禁用入口置灰：** 管理员明确要求移除不可用入口，因此不采用。专家和 SkillHub 的网络策略仍独立保留。

## 后果

后台与桌面端都需要更新版本才能使用可配置入口。修改在启动、登录及既有的窗口聚焦、页面恢复可见、五分钟认证计时刷新时应用，不增加轮询器。不增加数据库表、同级插件依赖或官方外壳补丁。针对性 API、后台界面和 Client 测试覆盖默认值、独立取值、无效配置、入口隐藏和页面关闭。原生平台验收仍属于部署检查。
