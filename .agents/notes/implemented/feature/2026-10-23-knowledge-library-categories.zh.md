# Agent Note：管理工作台知识库分类

Status: implemented

[English](2026-10-23-knowledge-library-categories.md) | 中文

## 问题

管理员需要按可见性命名知识库分组。固定的共性/共享目录标签不够用；管理工作台标签与桌面侧栏应跟随已创建的分类，「个人知识库」只保留未归类的个人库。

## 决策

管理工作台知识库页右上角提供「新建知识库分类」。弹窗的类型为「个人 / 公开 / 授权」（仅自己可见、所有人可见、订阅后可见）。OneAPI 据此写入 `type` 与 `require_auth`：个人 → `personal` 且需授权，公开 → `common` 且无需授权，授权 → `shared` 且需授权。管理工作台标签为「个人知识库」加各已创建分类（不再固定「共性知识库」「共享知识库」）。在个人标签新建未归类个人库；在分类标签新建时写入 `knowledge_bases.category_id`，并把分类类型复制到 `kind`。个人标签下的「全部人员」目录仅管理员（`isAdmin()`）可见；普通用户可进入同一管理工作台页面，走 `/api/knowledge-bases`，只看到自己的个人库卡片。「订阅审核」与「新建知识库分类」对每位登录用户可见；对应的 `/api/knowledge-admin` 分类与订阅审核路由使用 `UserAuth`。

`ListAuthorizedKnowledgeBases` 仅在 `category_id` 为 0 时保留原有类型规则。不需要授权的分类中，已上架知识库对每位登录用户可见。需要授权的分类中，已上架知识库仅对所有者或获得用户、部门授权的成员可见。已下架知识库保持隐藏。管理员仍收到完整目录。桌面侧栏为「个人知识库」、有库的公开分类、「我创建的」（自建授权分类库）以及「订阅知识库」（获批/被授权的非自建授权分类库）。授权分类名称不作为侧栏分组；其他人在订阅广场发现授权库，自建库以 `owned` 状态出现在广场。获批后出现在「订阅知识库」；见 [知识库订阅广场](2026-10-23-knowledge-library-subscription.zh.md)。只有管理员可以在创建知识库时指定 `category_id`。

## 考虑过的替代方案

**把分类编码成另一种 `kind`：**不采用。`kind` 是封闭的授权规则。分类还需要自己的名称和独立的授权开关，其中的知识库必须离开内置标签页。

**新分类只在管理工作台展示：**不采用。桌面用户会看不到管理员归入新标签页的知识库。

**类型仍用共性/共享/个人三项，并另加授权开关：**不采用。弹窗用个人/公开/授权直接表达可见性，并映射到既有 `type` 与 `require_auth`，避免两个互相冲突的控件。

## 后果

管理工作台和桌面需要与 OneAPI 的 `GET/POST /api/knowledge-admin/categories` 和 `GET /api/knowledge-bases/categories` 一起发布。分类名称唯一。桌面不在分类内创建知识库；创建留在管理工作台对应标签页。需要授权的分类，其授权编辑仍由管理接口与订阅审核路径负责。未分类知识库的类型规则见 [RAGFlow 知识库](2026-10-21-ragflow-knowledge-library.zh.md)。
