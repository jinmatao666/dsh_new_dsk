# Agent Note: Desktop skill installation and dependency grant

Status: implemented

[English](2026-09-01-desktop-skill-install-and-dependency-grant.md) | 中文

## Problem

桌面端用户需要在技能广场中安装技能，并让本地运行时能够发现它。Workspace Write 会话还需要在首次下载缺失依赖时征得用户确认，同时避免同一任务中不断重复打断用户。

## Decision

桌面安装包将官方技能包作为未启用的只读资源携带。技能广场仅把目录中的 slug 传给 Tauri 原生命令；该命令校验内置清单，并以原子方式将完整技能包复制到当前用户的 `.dsh/skills/<slug>/`。文件系统技能提供方只监听用户目录，因此内置技能在安装前不可用，新建对话会通过常规目录发现已安装技能。安装状态来自实际文件系统而非浏览器存储。升级和删除只接受清单匹配的市场技能或可识别的旧版市场 `SKILL.md`，不会改动无关的同名用户目录。

用户可通过技能广场添加完整的自定义技能目录。浏览器只提交用户选择的文件；原生命令校验全部相对路径、根目录 UTF-8 `SKILL.md`、其 kebab-case 名称、文件数量和总大小，再以原子方式在 `.dsh/skills` 下创建带标记的目录。只有带标记的自定义目录可以由该界面删除。“搜索”和“我安装的”均以正式技能和自定义技能的实际文件系统状态为准。

技能广场内置三个互相独立的 GIS_Service 技能包：地质条件分析、土地利用规划审查和三调土地利用现状分析。每个技能包分别拥有 `SKILL.md`、清单、PowerShell 调用脚本和接口说明。脚本可接收 GeoJSON、面要素 Shape 文件、仅含一套完整 Shape 数据的文件夹或安全的 Shape ZIP；校验必需的 `.shp`、`.shx`、`.dbf` 文件，读取面几何和可选 `.prj` 坐标参考元数据，通过 Windows PowerShell 调用已记录的服务端点，并在工作区保存带时间戳的原始 JSON、Markdown、Excel 与 Word 产物。Excel 包含分析结论页和接口明细页，Word 报告包含专业分析；脚本生成后会请求操作系统打开 Excel。脚本默认使用部署的 GIS_Service 地址，也接受显式参数或环境变量覆盖。每份接口说明定义模型可以解释的已确认返回字段；未列出的字段会被保留，不会被推断为规划或地质结论。

`ApprovalService` 可选择在一个存活会话中记住已允许的软件包管理器升权。它只识别记录在 `bash` 或 `pwsh` 工具调用中的 `pip`、`npm`、`pnpm` 和 `yarn` 安装命令。第一个匹配的升权仍进入正常人工审批；后续匹配升权在内存中自动允许，不再次弹窗。桌面端通过 `DSH_DEPENDENCY_INSTALL_APPROVALS=session-once` 启用此选项。

交付物行排除辅助源码扩展名，并只使用成功的文件变更位置，或终端中明确标记为生成、保存、写入、输出或交付的文件作为依据。终端生成的 JSON 与 Markdown 分析文件会和办公文档一起显示，不从助手文本推断产物。

NSIS 安装前和卸载前钩子会在替换内置 Node 运行时前结束 `ZJUGIS Harness.exe` 及其进程树；升级早期安装包时也识别旧的 `dsh-desktop.exe` 名称。随后只有可执行路径属于本安装目录 `resources/runtime/node.exe` 的孤儿进程会被结束。这样可释放 Sharp 的 `libvips-42.dll` 等原生模块，不会结束无关的 Node 进程。

桌面端发布矩阵在既有原生 Windows 和 macOS 目标之外，增加 Ubuntu 22.04 上的 Linux x64 构建。任务安装 Tauri 的 WebKitGTK 与打包前置依赖，暂存同一套桌面运行时，并将 `.AppImage` 与 `.deb` 产物随版本发布上传。

## Alternatives considered

**仅在浏览器存储中记录安装状态** — 不采用。浏览器标记无法将技能放入主机目录，也无法使新对话的目录发现到该技能。

**由渲染器向原生安装命令发送技能源码** — 不采用。渲染器提供的源码可能偏离已审查的技能包，并让网页内容有权创建任意用户技能。原生命令只安装随应用发布且通过校验的资源。

**应用启动时安装所有内置技能** — 不采用。预安装会让技能在用户选择前进入模型可见范围，也会使技能广场无法准确反映本机状态。

**首次依赖批准后允许所有后续沙箱升权** — 不采用。依赖安装授权不能扩展为与安装无关的命令或文件操作授权。

**跨会话记住依赖授权** — 不采用。新任务应重新获得用户决定，持久化授权还会带来撤销与审计要求。

## Consequences

技能广场安装的技能仅属于本机桌面端用户，并在下次对话的目录获取时可用。非桌面浏览器仍可渲染技能广场，但只有具备正式技能包的条目启用安装操作。Mock 条目仍可预览，并明确提示当前没有可安装包。

签入仓库的正式技能清单生成桌面端元数据。后台技能列表使用服务端 `skills` 记录；新增、编辑、删除、上架与下架都更新该来源。桌面端在登录后读取公开服务端列表，因此后台发布状态会在技能广场刷新后生效；服务端必须启用 `remote_skills` 能力。

桌面端侧栏在设置上方依次堆叠自动化、连接器、专家团和技能广场四个独立入口。每个入口拥有独立的覆盖层与导航状态；技能广场不再通过顶部产品页签切换这些页面。

自动化覆盖层目前是本地展示原型：已配置任务、模板、执行历史和创建表单仅保存在组件状态中。界面会明确说明，在专门接入这些服务前，它不会调度任务、新建对话或访问连接器。

连接器覆盖层同样是本地展示目录。它使用随应用打包的品牌风格 SVG 图标、紧凑卡片和单项详情展示预期授权范围，不收集凭据，也不会联系第三方服务。自定义条目仅保存在组件状态中，在具备受管连接器服务前会明确标注为演示。

专家库将单个专业角色与专家团区分开：单个条目描述未来可提供的 Agent 专家配置，专家团条目描述未来由多角色和技能组成的工作流。两类内容都只保存在组件状态中，不能暗示专家或团队已被实际创建、调度或执行。

技能安装优先使用公开 Tauri 桥接；外部 sidecar 页面缺少该桥接时，回退到持续存在的 Tauri 内部桥接。无论从技能列表还是详情页发起安装，成功与失败提示都保持可见。

GIS_Service 技能需要与服务数据坐标参考一致的面几何。Shape ZIP 只会解压到临时目录，并在请求后清理。每次调用保留带时间戳的原始响应 JSON、中文 Markdown、Excel 和 Word 产物。工作簿通过系统文件关联打开，也会出现在产物文件行中。报告记录已识别的输入、坐标参考元数据、已确认响应字段、记录数量以及适用的面积或分区结果。对话摘要以中文为主，端点名、文件名和字段代码保留原文；它可以解释技能接口说明中列出的字段，不会虚构未列出字段的规划或地质含义。

依赖便利只在已有升权路径后生效，不改变完全权限行为，也不放宽会话的通用沙箱策略。

Workspace Write 将已有输出文件名视为用户拥有的选择。智能体会询问用户是创建带版本号的新文件、先读取后覆盖已有文件，还是取消。完全访问模式由智能体自行选择新版本文件或覆盖已有文件，不再询问；但选择覆盖时仍必须先读取已有文件。

## Verification

聚焦审批和交付物测试覆盖会话授权与辅助源码排除。GIS 调用校验覆盖 GeoJSON、Shape ZIP、Shape 文件夹和直接 Shape 文件输入，以及带时间戳的 JSON 与 Markdown 产物。目录校验覆盖标识、版本、声明文件和路径限制；原生测试覆盖完整目录安装、升级、旧版迁移、所有权拒绝和删除。类型检查覆盖技能广场、审批和交付物包；Rust 检查覆盖桌面端原生命令。
