# Agent Note: OCR预览、下载与可选任务名称

Status: implemented

[English](2026-10-29-ocr-preview-download-workflow.md) | 中文

## Problem

用户需要在识别前检查所选文档，在查看结果的位置下载全部成果，并按格式查找文件。PDF 已作为输入格式支持，用户不需要重复导出 PDF，未命名任务也需要可辨认的默认名称。

## Decision

PNG/JPEG/WebP/BMP 使用浏览器文件对象预览。PDF/TIFF 使用要求登录、校验来源的本地渲染接口，沿用上传及页数限制。渲染不创建任务、不调用模型。文件和页码选择器同样可读取属于当前用户的历史输入。请求序号和取消控制器阻止旧响应覆盖新选择；会话失效时关闭放大预览并清除材料。

工作台为任务每个已发布文件提供下载入口，沿用现有原生保存及浏览器下载流程。成果页按实际输出扩展名筛选并显示数量。可选输出保留 TXT、Markdown、JSON、CSV 和 Word；历史 PDF 成果仍可下载。空名称使用首个文件名去掉扩展名后加分钟时间戳，服务端以北京时间补全，并遵守现有100字上限。

## Alternatives considered

**等待识别后再提供首次预览**会使用户无法在调用模型前确认选择的页面。

**在浏览器框架中嵌入 PDF**依赖桌面 WebView 的 PDF 支持，也与专家的严格框架策略冲突。本地 PNG 渲染让所有文档沿用同一个图片查看器。

**只在浏览器生成默认任务名**会让直接调用接口或浏览器补全失败的请求留下无名记录。服务端会在文件名校验后提供同样的补全。

## Consequences

PDF/TIFF 在识别前就会上传到专家服务进行预览。翻页可能再次发送编码后的原文件，大文档会增加传输耗时；文件仍被选择期间，浏览器复用编码结果。预览和识别相互独立。移除 PDF 输出会保留既有成果，工作台重跑历史 PDF 输出任务时默认改为纯文本。

## Testing

Python 集成测试验证未配置推理服务时可预览、不创建任务或调用模型、页码及文件切换、用户归属、损坏输入拒绝、空名称补全、移除 PDF 输出，以及 PDF 输入导出 Word。浏览器检查使用明确的本地 HTTP 替身，覆盖上传预览、PDF 翻页、文件切换、放大、空名称提交、直接下载 Word、筛选、空状态及移动端布局。
