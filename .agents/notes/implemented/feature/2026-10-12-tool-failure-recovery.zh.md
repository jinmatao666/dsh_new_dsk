# Agent Note: 跨步骤工具失败纠错

Status: implemented

[English](2026-10-12-tool-failure-recovery.md) | 中文

## Problem

模型收到明确错误后仍可能重复提交无效编辑，中间插入读取会重置连续计数，还可能花费多轮检查并不存在的差异。全局失败次数限制又可能提前结束有价值的工作，误伤临时重试。

## Decision

[repeat-tool-reminder 插件](../../../../packages/guard/repeat-tool-reminder/README.zh.md)通过工具执行前后及 agent 生命周期监听器提供可选纠错。[万维桌面端](../../../../packages/bundle/wanwei-desktop/cordis.patch.yml)启用此选项，官方 base 仍默认仅提醒。不修改 agent-loop 或各工具实现。

每个 agent 用有容量限制的哈希记录精确参数与失败身份，中间插入其他调用不会清除记录。失败结果收到已入日志、带来源归属的纠错指引，原始输出保持不变。结构化前台进程退出失败只收到建议，绝不视为参数无效。同一调用被确认参数错误三次后，执行前仅拒绝再次提交相同参数，修正后的参数仍可执行。精确调用成功、用户输入及空闲会清除状态。取消及下游执行后策略阻止不会训练检测器。模型仍可继续独立工作，插件绝不结束整个回合。

无效性仅限结构化 `INVALID_ARGS`，以及已确立的新旧编辑文本相同错误且实际参数确实相同。超时、权限、文件缺失、依赖下载及服务中断，都不能证明相同参数永远不能工作。哈希避免在私有状态中保留原始凭据，也避免提示再次引用凭据。

## Alternatives considered

**总失败次数达到限制就停止。** 不同失败可能属于独立工作，报错后仍可能取得进展。这样会让较弱模型放弃，而不是帮助纠错。

**只做连续调用提醒。** 中间读取会清除连续计数，让无效调用再次出现。失败记录能跨越这些读取。

**阻止所有重复失败或自动改参数。** 外部状态可能恢复，自动修改凭据或命令可能产生错误副作用。因此只限制已确认的相同参数错误，绝不自动重写参数。

## Consequences

纠错只为启用选项的 agent 增加有容量限制的状态和提示历史。它不能证明语义进展、捕获任意近似循环、保证模型遵从或阻止反复提出已被拒绝的调用。Loader 测试覆盖穿插读取、修正、临时重试、隔离、淘汰与卸载。无界面会话回放独立比较实际工作区编辑结果，不依赖模型自报完成。
