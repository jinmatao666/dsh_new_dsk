# Agent Note: 桌面端积分页面与主动签到

Status: implemented

[English](2026-11-04-desktop-credit-checkin.md) | 中文

## 问题

只有登录赠送配置、没有桌面可见入口，用户无法理解积分何时到账。切换主动签到后，已有首次请求活动不能再重复发放周期奖励。

## 决策

运营版沿用已有登录赠送配置作为主动签到规则。存储键保持不变，管理员看到签到赠送。按北京时间的自然日期和上次成功签到日期计算资格，未签到不补发。每日登录和首次请求的周期活动跳过自动发放，一次性活动保持独立。

侧栏快捷入口打开账户上方的积分与用量页面，仅在可以领取时显示。失败使用现有弹窗，成功使用现有浮动提示。通用设置快捷插槽和打开分区事件让产品行为留在私有插件内。

原子条件更新签到状态、插入积分账本和保存不可变回执在同一数据库事务内完成，并发请求不能重复发放。凭据留在 Host，仅允许固定的积分操作。明细合并个人积分到账与消耗日志，历史缺失的余额快照显示为空，不倒推补算。

## 考虑过的替代方案

用户明确选择主动签到，因此不采用登录或首次调用自动发放。现有定时积分账本已参与扣费，因此不新建另一套钱包。

## 影响

新版后台需要与桌面端配套部署，数据库迁移增加签到状态表和回执表。注册赠送、付费套餐及专家或技能的独立任务扣费不在本次范围内。窗口重新获得焦点或每分钟刷新签到状态，服务端在每次领取时重新校验资格。
