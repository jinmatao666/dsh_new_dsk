# Agent Note: 知识库发布审核与管理员待办箱

Status: implemented

[English](2026-11-12-knowledge-publication-inbox.md) | 中文

## Problem

个人知识库所有者需要向其他用户提供数据集，同时避免管理员审核前暴露文档。订阅审核也需要与发布工作一起放在明显的位置。

## Decision

运维版接受仅所有者可提交的个人知识库发布申请。待审和驳回时访问权限不变；只有管理员可以通过共享申请。直接选择发布目标与保留个人所有权遵循[保留个人入口的发布](2026-11-12-knowledge-publication-personal-origin.zh.md)。政务版拒绝提交与发布审核。

仅管理员可访问的知识库待办箱分为发布与订阅审核，显示待审数量并提供状态筛选。发布审核弹框展示申请范围和申请说明。申请专属文档接口仅允许读取待审申请的文档，不向普通管理员开放完整的个人知识库目录。驳回发布必须填写原因。每库保存最新发布申请，驳回后重新提交会替换之前的审核字段。删除知识库同时删除申请。

待办箱替换[知识库订阅广场](2026-10-23-knowledge-library-subscription.zh.md)的独立审核入口；该记录仍负责授权、广场发现与取消订阅语义。订阅列表与审核决定接口均要求管理员权限。

## Alternatives considered

提交时直接发布会在审核前暴露个人资料。复用订阅申请会混淆改变知识库可见范围与向用户授予访问权限。让所有者处理发布申请会取消管理员审核。查看某个待审申请不需要向管理员开放完整目录。

## Consequences

所有者提交发布申请前需检查整个知识库，通过后覆盖已有及后续新增内容。转为公共库后所有用户可读。转为订阅库后在广场展示，其他用户仍受授权检查约束。桌面待审状态和驳回原因来自持久申请。最新申请存储不会把每次驳回尝试保留为单独审计记录。

模型与 HTTP 测试验证审核前私有、两类目标、重新核对、重提申请、管理员授权与版本拒绝。客户端测试覆盖待审状态恢复和驳回反馈；工作台保存待审箱输出快照。本地刷新脚本将 Go 链接器临时文件保存在仓库所在盘。
