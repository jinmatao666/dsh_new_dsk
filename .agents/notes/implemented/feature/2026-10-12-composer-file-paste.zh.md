# Agent Note: 聊天框文档文件粘贴

Status: implemented

[English](2026-10-12-composer-file-paste.md) | 中文

## Problem

编辑器把粘贴文件交给图片入口，而桌面文档拖入已有复制到选定工作区并追加引用的流程。系统剪贴板文件列表格式也可能不产生 DOM 粘贴数据。

## Decision

[产品界面](../../../../packages/wanwei/product-ui/src/client/product.tsx)仅在所属可编辑聊天框拦截文档文件，复用既有导入命令，将剩余图片和文字转交编辑器，不改通用编辑器或图片行为。没有 DOM 内容的粘贴手势调用[原生文件列表命令](../../../../products/wanwei-desktop/src-tauri/src/clipboard_files.rs)。Ctrl/Cmd+V 仅在普通粘贴没有处理数据时安排兜底调用，原生空结果不添加内容。组件卸载清除计时器和监听器，立即设置的导入锁避免并发重复导入。

原生命令仅限主窗口，源文件仅从明确的系统剪贴板文件列表获取，不接受渲染层指定源路径或任意文本。本地文件 URL 由既有 URL 库解码。工作区复制、同名编号、拒绝符号链接、文件数及字节限制仍由原导入器执行。剪贴板读取使用维护中的 clipboard-rs 并关闭图片解码特性；Rust 依赖仅在桌面壳，不进入通用 DSH 或模型工具。

## Alternatives considered

**所有剪贴板文件都交给图片入口。** Office 和 PDF 不是图片，会错误拒绝拖入已支持的文件。

**把像路径的文本当作文件访问。** 普通聊天文本和网址不代表同意导入本地文件，只接受明确的剪贴板文件列表内容。

**替换通用编辑器粘贴行为。** 文档导入属于桌面产品，依赖其原生工作区命令。产品转交保留既有文字和图片编辑流程，无需让通用 DSH 了解 Tauri。

## Consequences

前端测试覆盖 Office/PDF、混合粘贴、其他输入框、原生兜底、去重、空列表、失败和卸载。Rust 路径测试覆盖中文、转义空格、原生绝对路径以及拒绝相对路径和网址。原生文件导入需要重新构建桌面壳。原生兜底不会覆盖非空的文字或图片 DOM 数据，发布前仍需验证 Windows/macOS 安装版剪贴板行为。
