# Agent Note: 服务端统一管理的百炼联网搜索

Status: implemented

[English](2026-09-20-server-governed-bailian-web-search.md) | 中文

## Problem

桌面端联网搜索依赖额外的本地 DeepSeek 凭据，但登录用户已经通过 OneAPI 使用问答模型。这会造成开发机可用、其他安装环境因缺少本地环境变量而失败，同时管理员无法统一指定检索所使用的付费模型与渠道。

## Decision

OneAPI 的“基础设置”同时保存默认搜索模型及其准确渠道 ID。下拉框只展示已启用且模型族支持百炼联网搜索的模型来源。每次标记为搜索的请求到达时，转发层会再次执行这些校验，并固定分发到所选渠道。渠道既可以使用专用百炼类型，也可以使用 OpenAI 兼容类型，因为百炼工作空间端点公开相同的兼容请求字段。

桌面端组合选用 `oneapi-bailian` 搜索提供方。它从 `/api/status` 读取公开的模型名称，使用现有桌面用户令牌请求 `/v1/chat/completions`，并且只给这次辅助请求添加 `X-Dsh-Web-Search: 1`。该标记通过身份认证及服务端路由校验后，OneAPI 才会注入百炼的 `enable_search` 和强制搜索参数。普通对话请求不会得到这些字段，仍按原有模型分发流程执行。

辅助请求在发出前以 `web/oneapi-search-request` 记录，不包含凭据。该事件登记在生成的持久化目录中，并标记为可忽略，因为旧版读取器跳过这一观察记录仍能重建对话。响应文本作为提供方内容返回；当百炼 OpenAI 兼容响应没有提供来源结构时，该链路不会虚构来源信息。

## Alternatives considered

**给每台桌面安装分发搜索 API Key。** 否决，因为这会重复分发密钥，并重新引入本次路由要消除的机器环境差异。

**让当前问答模型自行决定是否联网。** 否决，因为多数已配置模型没有原生联网能力，而且仅选择模型不能确定应使用哪个百炼渠道。

**给所有百炼对话请求添加搜索参数。** 否决，因为这会改变普通对话，增加成本与延迟，并让搜索行为取决于模型路由而非明确的能力调用。

## Consequences

管理员可以集中控制搜索成本与可用性，桌面用户只需现有登录令牌。配置的模型、渠道或绑定不可用时，搜索会明确失败。百炼新增或移除支持的模型族时，需要同步维护模型族白名单。如果管理员选择了不接受百炼搜索字段的兼容渠道，上游请求会明确失败，但不会改变普通对话行为。现有直接调用 DeepSeek 的提供方继续供非桌面组合使用。
