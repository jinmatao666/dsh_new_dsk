# Agent Note: 服务端统一管理的百炼联网搜索

Status: implemented

[English](2026-09-20-server-governed-bailian-web-search.md) | 中文

## Problem

桌面端联网搜索依赖额外的本地 DeepSeek 凭据，但登录用户已经通过 OneAPI 使用问答模型。这会造成开发机可用、其他安装环境因缺少本地环境变量而失败，同时管理员无法统一指定检索所使用的付费模型与渠道。

## Decision

OneAPI 的“基础设置”同时保存默认搜索模型及其准确渠道 ID。下拉框只展示已启用且模型族支持百炼联网搜索的模型来源。每次标记为搜索的请求到达时，转发层会再次执行这些校验，并固定分发到所选渠道。渠道既可以使用专用百炼类型，也可以使用 OpenAI 兼容类型，因为百炼工作空间端点公开相同的兼容请求字段。

桌面端组合选用 `oneapi-bailian` 搜索提供方。它从 `/api/status` 读取公开的模型名称，使用现有桌面用户令牌请求 `/v1/chat/completions`，并且只给这次辅助请求添加 `X-Dsh-Web-Search: 1`。校验通过后，OneAPI 将非流式标记请求转换到百炼原生生成端点，开启强制搜索和来源元数据。OpenAI 原样转发分支不能跳过这一转换。普通对话保留原有协议和路由。

辅助请求在发出前以 `web/oneapi-search-request` 记录，不包含凭据。该事件登记在生成的持久化目录中，并标记为可忽略，因为旧版读取器跳过这一观察记录仍能重建对话。原生 `output.search_info` 作为 `search_info` 保留在兼容格式的答案和 token 用量旁。拒绝重定向。非流式上游响应体及归一化后的桌面响应限制为 1 MiB。来源只取自上游检索元数据，不从生成正文构造。

适配器遵循[百炼搜索协议](https://help.aliyun.com/zh/model-studio/web-search)：`qwen3.6-plus` 等多模态 Qwen 模型使用多模态生成端点、文本内容数组和上游 SSE；纯文本模型保留文本生成端点。SSE 答案、检索来源和累计用量汇总成桌面现有的非流式响应。无效、中断或报错的流明确失败，不把半截答案作为成功搜索结果返回。

SSE 直接从响应读取器解析，分别限制原始流量 32 MiB、单帧 256 KiB、答案正文 128 KiB，以及最多 64 个、合计 128 KiB 的来源。重复来源按 URL 去重，没有 URL 时按序列化元数据去重。累计用量取最后一帧而不是相加。任何限额超出时，均在写入成功响应前失败；重复来源元数据不会仅因出现在多帧中就耗尽桌面响应的 1 MiB 限额。

OneAPI 为公开 `web_search` 函数的对话请求和标记搜索请求追加服务端当前北京时间日期（`Asia/Shanghai`，UTC+08:00）。保留既有系统指令和用户明确指定的日期。日期上下文计入提示词 token 统计；OpenAI 原样转发请求只修改系统内容，保留厂商扩展字段。没有此能力的请求保留原有提示词。该策略使用服务器时钟而非桌面时区；注入的上下文不包含在桌面端转发前的请求事件中。

## Alternatives considered

**给每台桌面安装分发搜索 API Key。** 否决，因为这会重复分发密钥，并重新引入本次路由要消除的机器环境差异。

**让当前问答模型自行决定是否联网。** 否决，因为多数已配置模型没有原生联网能力，而且仅选择模型不能确定应使用哪个百炼渠道。

**给所有百炼对话请求添加搜索参数。** 否决，因为这会改变普通对话，增加成本与延迟，并让搜索行为取决于模型路由而非明确的能力调用。

**提高单一原始响应限额，或重试每次超限结果。** 否决，因为重复 SSE 元数据不等于答案大小；有界的增量解析区分两者，避免无界缓冲和重复付费请求。

## Consequences

管理员可以集中控制搜索成本与可用性，桌面用户只需现有登录令牌。配置的模型、渠道或绑定不可用时，搜索会明确失败。百炼新增或移除支持的模型族时，需要同步维护模型族白名单。所选渠道必须公开原生生成路由；只支持兼容对话的代理会明确失败。渠道基础地址可带 `/compatible-mode/v1` 或 `/api/v1` 后缀，搜索适配器会归一化。现有直接调用 DeepSeek 的提供方继续供非桌面组合使用。本地测试覆盖原生转换、原样转发隔离、来源、用量、无效响应、重定向拒绝、大量重复元数据流、有界失败及北京时间跨日上下文。服务器时间必须正确；日期指引不能保证事实准确。付费真实模型验收另行执行。
