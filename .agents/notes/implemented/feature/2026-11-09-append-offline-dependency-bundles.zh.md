# Agent Note: 追加离线依赖包

Status: implemented

[English](2026-11-09-append-offline-dependency-bundles.md) | 中文

## Problem

管理员需要在大型基础 wheel ZIP 上追加依赖，无需重新打包或重传基础包。资源来源选择仍遵循[内网资源决策](2026-10-19-intranet-resource-sources.zh.md)。

## Decision

OneAPI 在持久化资源目录中，通过原子替换文件发布不可变上传包的版本化目录索引。上传处理器在同一后台进程中串行执行导入和目录发布。合并后的 pip 列表保留各 wheel 原有的按内容寻址下载 URL 和 SHA-256 片段。不区分大小写的文件名相同且大小、哈希一致时，只展示一条记录；内容冲突则拒绝发布。不同版本文件名可共存，pip 解析所需版本。首次追加时将原先唯一生效的包纳入目录，未生效的历史目录不纳入。

## Alternatives considered

替换生效包需要重新分发大型基础包。覆盖同名 wheel 会破坏不可变 URL，并掩盖不一致的发布。要求每个功能独占一个 ZIP 又无法满足小包增量交付。目录索引因此将上传元数据与不可变文件分开保存。

## Consequences

上传立即生效，独立于资源方式设置的保存。重复上传完全相同的包为幂等操作。发布失败保留原有目录索引。重叠上传可能重复占用磁盘，冲突拒绝也可能留下未索引目录；自动清理、删除、回退界面和多个后台进程共享目录的协调均不在本次实现内。备份需同时包含目录索引及资源目录。

专项 HTTP 测试覆盖追加、去重、冲突回退、原有生效包、并发上传及下载链接保留。真实 pip 测试禁用外部索引和缓存，安装依赖基础包内容的补充包，并导入两者。按需启用的交付归档测试上传运维提供的 ZIP，追加补充包，通过本机 HTTP 列表安装 openpyxl 和补充包，并创建工作簿。安装版桌面经过部署网关执行任务仍需发布运维验收；这些测试不覆盖该网关或全部二进制 wheel/Python 组合。
