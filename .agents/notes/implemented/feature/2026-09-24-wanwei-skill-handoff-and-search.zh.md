# Agent Note: 万维技能草稿接续与受管搜索

Status: implemented

[English](2026-09-24-wanwei-skill-handoff-and-search.md) | 中文

## Problem

万维桌面端需要让技能市场中选中的技能在尚无工作区时成为可编辑的 Conversation 草稿。产品还需要审核结果未读提醒和管理员指定的 OneAPI 搜索模型，同时不能把万维业务放进官方 DSH 包。

## Decision

官方 Conversation 输入解析器持有一份无会话文本草稿，并在连接工作区后将其转入对应 Session，但不自动发送。可选的草稿前缀 Slot 接收当前文本和通用的删除前缀动作。没有产品注册时，官方实现不认识技能或万维，也不显示前缀。

万维技能市场预置所选技能的斜杠标记，记录显示名称，并注册前缀展示组件。它根据成功读取的个人审核列表记录审核结果变化；用户打开相应的通过或驳回筛选时清除未读提醒。万维 OneAPI Host 插件注册 `oneapi-bailian` Provider，产品 Bundle 选择它而非官方搜索 Provider。每次搜索都读取服务端选定的模型，并在请求时解析当前用户的令牌。

## Alternatives considered

**在产品包复制官方输入组件。** 这可以避免增加少量上游接口，却会形成第二套编辑器和输入生命周期。

**在官方输入组件中直接识别技能。** 这样便于绘制标记，但违反产品边界，并让上游升级依赖市场业务语义。

**用桌面本地密钥配置搜索。** 这会绕过管理员模型策略，也会重复配置凭据。

## Consequences

技能市场和 OneAPI 实现均保留在官方包之外。上游兼容清单增加一份通用草稿状态和一个可选展示 Slot。无会话草稿在用户选择工作区前只保存在本机；选择技能本身不会发送请求。搜索需要可连接的 OneAPI 服务和已登录令牌。
