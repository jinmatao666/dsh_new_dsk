# Agent Note：桌面公开注册与统一登录

状态：已实现

[English](2026-11-04-desktop-public-registration.md) | 中文

## 问题

短信和扫码入口仅提示不可用。公开注册未采用管理员指定的默认角色，短信校验忽略手机验证码有效期配置。

## 决策

现有登录卡片接入固定Host短信登录、明确确认的注册、找回密码和微信扫码。未注册手机号须同意协议，密码选填；已有手机号保留账号ID和角色。未绑定账号的微信先手机号登录或注册再绑定。已有微信账号缺少手机号时，通过Host持有的短时Cookie补绑原账号。离开页面取消请求，更换二维码废弃旧状态。

新公开注册由服务端分配角色，未指定时按名称匹配已有“注册用户”。只接受启用的普通成员角色，默认角色不能直接删除、停用或在按名匹配时改名。已有账号及管理员创建用户的角色逻辑不变。后台提供仅超级管理员可改的登录配置和同页默认角色选择，其他工作台配置权限不变。短信执行配置有效期、一分钟发送间隔和每小时上限。

微信接入路线待定期间，桌面扫码入口暂时恢复原有未开放浮动提示，保留当前表单且不调用公开二维码接口；账号和短信入口继续可用。

新手机号确认协议并验证后直接进入主界面，再通过原生弹窗可选设置密码。服务端提供十分钟内单次有效的首次设置资格，不重复发短信，已有密码的账号拒绝此接口；后续改密沿用验证流程。资格保存在进程内，重启或请求到其他副本时需走普通账户设置流程。后台同页分为注册、短信和协议三个区，开关使用开启／关闭下拉框，隐藏固定技术参数和待接入微信配置。登录表单字段和按钮位置及底部三行文字统一，无内部滚动条。

后台短信登录下拉框保存时同步 PhoneLoginEnabled 与 SMSEnabled，短信签名隐藏并保留。账户安全操作使用随包许可图标和可键盘聚焦的绑定手机号提示。积分明细保留变动后余额，并增加首页／末页及有范围校验的页码跳转。

短信提交采用页面“登录即表示同意”的确认方式，不再要求单独勾选。底部链接以原生顶层弹窗展示后台协议与隐私正文。新用户注册仍要求两份正文齐全，已有账号的短信登录不受影响。选项行提示验证码五分钟有效，账号、连接、短信、找回密码异常及扫码未开放提示统一通过可关闭的原生弹窗展示，避免与页脚重叠；关闭提示保留表单输入。

## 考虑过的替代方案

未注册登录时自动建号会跳过协议确认。已有微信账号再次建号会分裂身份。按编号推断角色可能授错权限。只在页面限制配置不能保护直接接口调用。

## 影响

后台和桌面须同时更新。阿里云凭据、审核通过的签名和模板、微信网站应用及可访问的回调地址、最终协议和隐私政策正文仍需配置，未擅自启用。没有发送真实短信、执行微信授权或修改生产账号。测试使用隔离SQLite账号中心表和模拟认证返回。默认分配需要已有启用的“注册用户”，或明确指定其他普通成员角色。

## 测试

专项测试覆盖登录／令牌／模型兼容、短信注册会话建立、协议确认、注册引导、找回密码、取消请求和微信补绑手机号。后台测试验证角色分配、老账号保留、验证码单次使用、密码重置持久化、配置权限、已认证短信／限流及有效期。后台页面测试验证只保存变更项、保留密钥、失败重试、默认角色选择及原有系统页签。类型检查、专项lint和浏览器PNG预览验证修改面。短信送达和OAuth须配置后实测，尚未验证。
