# Agent Note：统一后台选择控件

状态：已实现

[English](2026-10-21-admin-select-unification.md) | 中文

## 问题

后台页面混用了原生 select、CustomSelect、Semi Select 和 Semantic 选择下拉框。原生菜单受操作系统影响，不符合圆角主题；表单或表格滚动区域中的行内自定义菜单可能被裁切。

## 决策

将角色权限、专家分类、模型配置和用量页面中剩余的原生下拉框替换为 CustomSelect。保留选项、值和事件契约，包括禁用选项与省略 value 的选项。自定义列表通过 portal 挂到 body，测量并匹配触发器宽度，随滚动和窗口变化定位，空间不足时向上展开。保留键盘选择、Escape、点击外部关闭与焦点恢复。

对保留的 Semi 和 Semantic 控件应用共享后台样式，不重写它们的搜索与多选行为。菜单统一使用圆角、内缩选项行、浅蓝选中态和柔和阴影。选择菜单跟随触发器宽度；命令菜单保持适合内容的尺寸，并采用同样的圆角风格。兼容暗色模式和减少动画设置。

## 考虑过的替代方案

仅给原生 option 加样式无法可靠改变系统绘制的菜单。全面替换组件库选择控件会不必要地重写筛选、多选逻辑。共享样式加定点替换原生控件，可以保留既有行为。

## 影响

选择控件统一使用既有主题，不改变后台配置或数据契约。Portal 菜单位于滚动容器之外，因此测试通过无障碍 ID 定位列表，不再依赖 DOM 父子关系。

## 验证

后台前端全部 72 项测试通过，包括新增 CustomSelect 测试与更新后的角色、发布记录回归。生产前端构建成功。无头浏览器检查构建后的角色弹窗，覆盖桌面与窄屏宽度，并检查代表性 Semi/Semantic 页面，验证菜单对齐、圆角、弹窗层级和选择操作。不涉及接口或数据库变更。以上为本地验证，并非生产部署。
