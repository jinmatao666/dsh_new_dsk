# Agent Note: 会话持久化使用不触发 hook 的 JSON 序列化

Status: implemented

[English](2026-09-20-hook-free-session-json-serialization.md) | 中文

## 问题

`Session.append()` 在接纳事件前会校验并快照事件数据和 surface 元数据，但 JSONL 后端随后仍把这些已接纳对象交给原生 `JSON.stringify`。原生序列化会调用对象自身或继承的 `toJSON` 方法，因此环境中的原型扩展可能只在持久化时改写已经校验的值；已观察到一条 assistant 消息把扁平来源序列 `766..864` 存成 `[[766,864]]`，导致下一次加载历史时拒绝该事件。

## 决定

`@deepseek-ai/dsh-session` 提供 `stringifyJsonValue(value)`，以迭代方式序列化现有无损 JSON 值集合。它先快照输入，再按结构输出数组和记录，只对标量字符串及对象键使用原生字符串转义，并且绝不调用 `toJSON`。JSONL 后端将其用于会话 header 以及每条事件或打包分片行。写入时校验仍是首个拒绝点；不触发 hook 的序列化保证持久化步骤不会改变已经接纳的值。

## 备选方案

**加载时展开嵌套的来源区间。** 未作为主要修复，因为 `[[start,end]]` 不是会话格式，而且这种做法可能掩盖其他序列化阶段改写。预发布存储会拒绝当前格式中的异常数据，而不是猜测修复方式。

**检测到 `Array.prototype.toJSON` 时拒绝日志。** 否决：无关的应用代码也可能安装 hook；既然持久化层可以确定性地序列化已校验值集合，就没有必要让所有会话写入失败。

**调用 `JSON.stringify` 前临时移除原型 hook。** 否决：修改全局原型会影响整个进程，并与并发序列化产生竞态。

## 结果

会话 JSON 编码会在输出文本前额外执行一次迭代快照。这项分配开销换来不受环境 `toJSON` hook 影响的确定性持久字节，并同时适用于压缩和原始 JSONL 存储。已经损坏的日志仍然无效；本次没有加入兼容性解释。
