# Agent Note: SQLite 令牌额度结算

Status: implemented

[English](2026-11-23-sqlite-token-quota.md) | 中文

## 问题

SQLite 拒绝令牌额度更新中的 `GREATEST`。旧模型结算路径可能已经扣减账号并记录消费，但令牌剩余及已用额度没有变化。后续成功的令牌更新也可能掩盖之前的账号错误。

## 决策

令牌扣减和退款复用已有的数据库方言兼容、下限为零的 SQL 表达式。带符号的批量更新差额保持相同语义。`PostConsumeTokenQuota` 在账号操作失败时先返回错误，不再调整令牌额度。[模型额度记账](../../../../services/one-api/docs/model-quota.md)定义核验方法。

## 考虑过的替代方案

**读取令牌后计算剩余额度。** 并发请求可能互相覆盖；原子表达式保留现有更新行为。

**对历史失败的令牌更新重新收费。** 账号可能已经支付。历史余额需要按请求核对，不能自动重放账号扣费。

## 影响

SQLite、MySQL 和 PostgreSQL 使用相同的令牌更新语义。旧路径的账号和令牌写入仍是独立操作；此修复不承诺二者之间的事务回滚。回归覆盖扣减、退款、下限为零的批量差额、账号错误传递，以及转发日志与实际余额的一致性。
