# Agent Note: 有界知识库大文件上传

Status: implemented

[English](2026-10-22-bounded-knowledge-uploads.md) | 中文

## 问题

知识库上传上限为 20 MiB。将完整文件读入 JavaScript 数字数组并通过 RPC 序列化会放大内存占用；只提高上限会使大文件选择不安全。用户报告的 MDB 白屏尚未复现，不能确定归因于大小检查。

## 决策

桌面接受最大 1 GiB 的文件，并按顺序发送 1 MiB RPC 分片。认证后的 Host 校验声明大小、偏移及字节值，最多允许一个活动文件，并写入随机命名的私有临时目录。完成操作要求实际字节数等于声明值，并使用文件支撑的 Blob 进行 multipart 转发。失败、完成、取消、空闲过期及等待完成的插件卸载均会删除临时文件。空闲间隔通过 `knowledgeUploadIdleTimeoutMs` 配置。

OneAPI 允许 1 GiB 文件加有界 multipart 包装，检查实际文件大小并清理 multipart 临时文件。RAGFlow multipart 包装使用小缓冲区和包裹原始来源的 `io.MultiReader`；只有上传转发采用 30 分钟 HTTP 超时。桌面出错后仍保留知识库页面及可用的上传控件。

## 考虑过的替代方案

**只提高常量。** 完整文件 JSON 序列化和服务端完整 multipart 缓冲仍会放大内存占用。

**通过通用桌面 HTTP 桥发送单个大请求。** 该桥会缓冲请求体，并限制为 300 MiB。有界知识库 RPC 分片避免修改共享传输行为。

## 影响

上传需要本机临时磁盘空间，并按顺序执行；不提供跨应用重启的断点续传。RAGFlow 或部署代理仍可能拒绝文件，其错误必须保持可见。本次不增加 MDB 解析。原文件下载、预览及跨库转移仍保留独立的 20 MiB 限制。进程崩溃可能遗留临时文件，与正常卸载不同。

## 测试

定向测试覆盖超过 20 MiB 的文件、禁止完整文件读取、分片顺序、不完整提交、1 GiB 元数据边界、空闲过期、未认证拒绝、上游失败及页面恢复。Go 测试覆盖超过原上限的 MDB multipart 上传，并验证来源仅在 HTTP 分发后读取。这些测试使用本地或 mock 服务，不连接真实 RAGFlow 部署，也不读取用户的数据库文件。
