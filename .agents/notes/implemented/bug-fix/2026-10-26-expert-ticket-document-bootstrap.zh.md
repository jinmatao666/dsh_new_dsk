# Agent Note: 在受信任文档中初始化专家票据

Status: implemented

[English](2026-10-26-expert-ticket-document-bootstrap.md) | 中文

## 问题

异常 Mac 请求到达 Nginx 时，HTTP 路径包含 `%23ticket=`，工作台加载前便返回 401。启动票据签发成功。原生日志确认视图创建和导航，但不能定位是哪次原生转换产生了编码路径。

## 决策

原生导航使用不带片段的已验证入口。文档启动脚本通过 history 替换，在网站脚本运行前恢复片段，仅作用于来源、路径和查询参数均与登记值一致的顶层文档。由启动 URL 摘要派生的 sessionStorage 标记防止刷新后复用票据。服务端仍核验短时、单次票据；提供方凭据不进入注入脚本。

## 考虑过的替代方案

网关接受编码后的票据路径仍会把凭据写入 HTTP 日志。查询参数也会让票据进入请求日志。禁用认证会移除身份保护。文档初始化保留现有网站协议，不依赖原生片段转换。

## 影响

只需重建桌面端。服务端路由、专家网站和 F12 设置不变。初始化要求第一方 sessionStorage 可用，且入口不经过改变路径或查询参数的中间重定向。此修复不证明是哪个 macOS 或 WebKit 版本导致转换。现有视图生命周期决策仍独立有效。

## 验证

Node VM 测试执行生产初始化脚本，覆盖首次交接、刷新、新启动、来源／路径／查询不匹配和子框架。Rust 测试验证脚本参数及启动地址分离。Windows Rust 测试通过；宣布事件解决前仍需异常 Mac 安装版和 Windows／macOS／Linux 原生回归。
