# Agent Note：通过面板主体保留专家工作台高度

状态：已实现

[English](2026-10-21-expert-workbench-flex-height.md) | 中文

## 问题

活动专家标签的原生视图占位容器可能高度为零。面板与专家容器使用弹性尺寸，但中间的面板主体是块级容器。活动工作区取消最小高度后，内容因此塌陷。有效尺寸判断阻止创建或隐藏原生子视图，导致两个桌面平台的工作台空白。

## 决策

仅在活动工作台模式下，将面板主体设为纵向弹性容器，取消底部内边距和独立滚动。专家容器与原生视图占位容器填满可用高度。返回目录后移除该模式，恢复普通目录滚动。保留原生最小尺寸校验，不通过打开无效视图掩盖布局缺陷。

每个已挂载的启动实例串行执行原生子视图操作。创建返回前先隐藏子视图，渲染端等待定位完成后再显示。清理先等待正在执行的操作，再隐藏并关闭，避免迟到的显示请求覆盖其他功能页面。可见性调用失败不提交缓存状态。目录移除失败标签，关闭失败重试一次，原生隐藏或关闭后恢复主视图焦点。原生定位和可见性命令使用异步处理，避免向 UI 线程派发操作时阻塞同步命令处理器。

Windows 主视图和专家视图共享浏览器参数常量。WebView2 拒绝为同一浏览器数据目录创建参数不同的第二个环境。Wry 原生创建失败时，Tauri 子视图构建器仍可能返回派发器；Wry 在创建浏览器环境前已创建可见子容器，可能使不可用子窗口覆盖主页面，却没有可导航的 WebView。因此，创建成功返回前读取原生尺寸，Windows 显示／隐藏命令确认控制器实际可见性。诊断保留尺寸查询的原始错误，并串行写入 JSON 行。

## 考虑过的替代方案

固定工作台高度会在较小窗口溢出，在较大窗口浪费空间。移除原生尺寸判断仍会留下无效布局。补全弹性布局链，使原生占位容器在启动、侧边栏变化和窗口缩放后获得可用尺寸。

调整窗口大小可以刷新原生尺寸，但无法修复视图归属或请求顺序。原生调用确认前缓存可见状态会阻止隐藏失败后的恢复。不等待关闭会使正在执行的显示请求超出组件生命周期。串行执行这些操作保留原生网站会话，不依靠缩放窗口恢复。

## 影响

Windows 只读采样将控制器父句柄与主窗口有数量限制的后代树、鼠标命中归属及 UI 线程焦点／捕获关联。只保留固定窗口类别和几何／状态，不读取窗口文本或外部应用窗口树。即使 DOM 点击没有送达，也能为原生遮挡提供线索；但事件后采样不代表缺失点击发生瞬间的精确命中。

诊断修订版 2 区分已排队操作与回读结果，并用视图摘要标识关联。操作耗时、请求尺寸、原生错误、生命周期阶段、回调超时和关闭后查询可定位实例停止推进的环节。捕获／冒泡／处理后 DOM 信息包含禁用状态和弹窗数量，不收集用户内容。进程上限明确记录截断。仅凭未观测到 DOM 输入，不能断定是哪个原生窗口拦截了真实点击。

Windows 的 `check:expert-window` 验证程序将浏览器数据和本地回环 HTML 测试页与已安装用户数据隔离。它复现浏览器参数不一致的故障，并验证五轮修复后的创建／加载／显示／定位／隐藏／关闭、主视图缩放及程序触发的 DOM 处理函数。它复用生产浏览器参数和可见性确认函数，不验证真实鼠标命中、生产票据或 macOS／Linux 行为。

原生输入排查使用有上限、不含内容的诊断记录，不从已排队命令的返回值推断清理成功。专家诊断激活后，仅主视图报告结构化点击信息，原生快照读取视图清单、尺寸、焦点和 Windows 控制器可见性。隐藏／关闭及缩放后采样，可与 DOM 点击送达情况对比。这些记录不证明父窗口消息处理是故障根因；该判断仍需 Windows 安装包复现验证。

修复位于共用 Client CSS，不改变专家地址、票据或服务器部署。浏览器回归启动桌面 profile，使用真实面板与专家插件，仅模拟外部后台和原生桥接，在启动、缩放、标签复用、关闭和目录恢复过程中测量真实元素尺寸。只模拟矩形尺寸的组件测试无法发现此问题。重新构建后仍需对 Windows 和 macOS 原生安装包进行平台验收。
