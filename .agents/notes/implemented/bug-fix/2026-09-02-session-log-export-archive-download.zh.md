# Agent Note: 在浏览器下载前获取会话归档

Status: implemented

[English](2026-09-02-session-log-export-archive-download.md) | 中文

## 问题

Session log 操作原先通过 `HEAD` 请求确认导出端点存在，再将端点 URL 交给 HTML 下载锚点。桌面 WebView 可能接受该点击却不创建保存文件，因此界面显示成功时实际上还没有传输 ZIP 归档。

## 决策

`dsh-session-log-export` 使用 `GET` 请求导出端点并等待收到 ZIP 字节。在浏览器中，它创建 Blob URL 并触发普通浏览器下载；在桌面 WebView 中，它将已获取的字节通过可信 Tauri bridge 交给 `save_session_log_archive`，写入当前用户的“下载”文件夹。原生命令拒绝不安全文件名且从不覆盖已有导出；同名文件会追加数字后缀。只有浏览器下载手势或原生写入成功后才显示成功。

## 备选方案

**保留 `HEAD` 校验后使用 URL 锚点。** 不予采用，因为它只能校验端点可用，不能证明已经获取归档，也不能证明桌面 WebView 已保存文件。

**在所有环境中都使用 Blob URL。** 经桌面端验证后不予采用：外部 sidecar WebView 可以接受锚点点击，但不能可靠地落盘文件。两个环境仍获取同一份归档字节，只有最后的保存操作按平台区分。

## 影响

导出会在完整 ZIP 响应返回后才显示成功，因此大型归档的“正在准备”状态会比原先仅发请求头时更久。浏览器用户获得 Blob 支撑的下载，桌面用户获得已验证写入“下载”文件夹的文件。原生写入失败会显示导出错误，不会再出现虚假的下载成功提示。
