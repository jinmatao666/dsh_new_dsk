# Agent Note: 跨预设作用域的桌面技能目录

Status: implemented

[English](2026-10-21-desktop-preset-skill-roots.md) | 中文

## 问题

Web bundle 停用了主进程的文件系统技能提供方。Agent 预设分别挂载提供方，其默认行为扫描共享用户 agents 目录和父级 Git 根。只配置已停用的主进程行，无法限制这些实际运行的提供方。草稿目录还使用用户主目录作为 cwd，虚构了一个工作区。

## 决策

桌面端挂载主进程拥有的文件系统发现策略，并启用主进程提供方来提供已安装技能。所有后代文件系统提供方都读取该服务，以确定项目根选择和共享用户目录发现规则。策略发布和释放会使提供方目录缓存失效。未挂载策略的通用 profile 保留默认行为，显式自定义及内置根目录继续受支持。

会话创建前的目录省略 cwd，会话目录仍使用实际工作区和预设作用域。不删除技能文件；策略用于目录发现，而非进程隔离。

## 考虑过的替代方案

**只修改随包预设 YAML。** 用户本地复制的预设保留自身默认值，仍可能复现混入问题。统一的主进程策略也覆盖未来预设，不必修改用户文件。

**删除外部技能或在客户端隐藏。** 删除会影响其他应用；客户端过滤仍让模型加载器访问这些外部技能。发现阶段在两类消费者读取目录前执行限制。

## 影响

桌面端增加一个主进程服务和导出的插件入口。回归测试经 Loader 加载桌面策略，再经常驻预设作用域挂载随包标准、PTC 和 Cordis 预设中的文件系统行，验证允许与排除的技能名称。通用默认值、策略缓存失效及无损释放另有测试。已安装应用需要重新构建并重启桌面 Host 才能获得修改。
