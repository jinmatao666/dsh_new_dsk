# Agent Note: 在 Workspace Write 输出重名时询问用户

Status: implemented

[English](2026-09-02-workspace-write-output-collision.md) | 中文

## 问题

文件系统观察策略能够正确拒绝未读取过的覆盖写入，但原先需要模型先看到报错再自行补救。因此 Workspace Write 用户看到的是失败的 Write 卡片，而不是对已有输出文件如何处理的询问。

## 决策

`write` 工具现在会在请求写入意图前检查已解析的目标路径。在 Workspace Write 模式下，目标是已有普通文件时会询问用户：创建新版本、覆盖或取消。创建新版本会查找同目录下类似 `report (2).docx` 的名称；覆盖则会先读取现有文件，再进行受保护的替换。在所有非交互模式（包括完全访问）下，工具会先读取已有普通文件，再不询问地写入。

## 备选方案

**仅保留系统提示词。** 不予采用，因为模型可能在读取前直接写入，先产生策略错误后才能询问用户。

**始终创建带序号的新文件。** 不予采用，因为用户可能明确需要替换已生成的草稿，而 Workspace Write 应让这个决定对用户可见。

## 影响

Workspace Write 现在会在同名普通文件写入前暂停，并且除非用户选择覆盖，否则保留原文件。完全访问保持不中断，同时仍满足安全替换所需的新鲜度观察。预检查与实际写入之间若发生并发变更，仍会通过现有版本保护失败，而不会静默覆盖数据。
