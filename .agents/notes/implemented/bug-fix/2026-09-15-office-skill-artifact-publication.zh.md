# Agent Note: 办公技能产物发布

Status: implemented

[English](2026-09-15-office-skill-artifact-publication.md) | 中文

## Problem

办公技能会同时生成用户需要的最终文件、提取索引、回滚数据和处理报告。发布全部路径会让内部 Markdown 和 JSON 文件与用户真正要求的文档、PDF 或图片混在一起。运行结果失败后还可能被当成普通终端文本再次扫描，导致输入文件和诊断文件被错误显示为成功产物。

## Decision

`WANWEI_RESULT` 标记是办公技能产物的权威来源。客户端直接从持久化工具结果文本读取该标记，包括没有终端结果视图的后台任务收集结果。有效标记包含 `success: false` 时不发布任何文件；只要标记有效，就不再经过通用终端路径后备识别。

办公运行时只把面向用户的文件放入 `artifacts`。临时提取文件和恢复元数据使用独立结果字段，不进入产物栏。各技能按任务选择交付文件：文档对比发布 Word 和 HTML，文档摘要发布 Word，批量重命名执行后发布改名后的文件，图片处理发布处理后的图片。

## Alternatives considered

**由客户端根据扩展名推断主要文件。** 扩展名规则无法判断 JSON 是用户要求的分析结果还是内部恢复状态，而且会把单个技能策略写入桌面客户端。

**依赖模型在最终回复中点名文件。** 模型文字不是可靠的工具输出记录，可能遗漏、打乱顺序或错误分类运行时生成的文件。

**发布运行时生成的全部文件并依靠描述区分。** 这种方式仍会向用户暴露内部实现文件，并可能让主要交付物被隐藏在折叠区域中。

## Consequences

产物栏展示前台命令和后台任务生成的用户办公结果，不再混入内部 Markdown 或 JSON。每个办公技能继续负责选择自身产物，客户端只执行统一标记规则，不写死技能名称。内部恢复文件仍可供运行时使用，但不会作为用户交付物显示。
