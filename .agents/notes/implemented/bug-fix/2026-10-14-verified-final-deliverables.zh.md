# Agent Note: 校验最终交付文件

Status: implemented

[English](2026-10-14-verified-final-deliverables.md) | 中文

## 问题

从修改日志推断最终产物可能展示中间文档、重复展示相对路径和绝对路径，或在收尾回复不点名文件时漏掉成果。技能自动工作区也需要精确到秒的时间戳来减少重名。

## 决策

私有 Host 组合注册 `deliver_files`。它通过会话文件系统解析路径，要求普通文件真实存在，并按文件系统身份去重。完整清单覆盖同一轮次中之前的声明。成功执行文件或终端操作后，如果没有更晚的声明，受限的轮次结束提醒向模型 steer 一次。

UI 从根工具调用结果读取交付声明。空清单或失败的声明清空产物行。没有声明时，当前包含回复的历史要求可解析的收尾引用，不猜测所有修改过的文档。过程文件保留在磁盘。自动工作区名称使用本地 `YYYYMMDDHHmmss`；同一秒重名仍通过独占创建目录和数字后缀处理。

## 考虑过的替代方案

**增加文件名猜测规则：**临时名称和文档扩展名不能确认最终意图，也不能规范化文件系统别名。

**无限重试收尾：**模型重复遗漏不能造成无界轮次。提醒限制为一次尝试。

## 后果

文件存在性和身份由程序确定；最终意图和文档质量仍依赖任务执行与模型选择。模型必须直接调用工具，不能通过嵌套调用。没有正确声明或引用时，UI 可能不展示文件，而不是展示推断出的中间文件。安装版桌面端与真实模型仍需验收。

## 测试

聚焦的 Loader 与文件系统测试覆盖真实文件、路径别名、缺失文件、目录、空清单和资源释放。会话测试覆盖声明优先、替换、空清单以及实时追加与重放一致性。原生文件系统测试覆盖十四位工作区名称分配和重名。
