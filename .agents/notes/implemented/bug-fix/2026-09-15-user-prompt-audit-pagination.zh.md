# Agent Note: 用户提问审计分页

Status: implemented

[English](2026-09-15-user-prompt-audit-pagination.md) | 中文

## Problem

模型日志页面只加载固定的一批用户提问审计记录，管理员无法查看更早的内容。在数据库偏移之后再过滤框架生成的消息，也可能导致分页之间出现重复或遗漏。把每次上游模型请求分别记录为用户问题，会让同一个桌面端回合随工具循环重复出现；读取旧 `users.username` 字段还会暴露账号中心占位符，而不是真实登录名。

## Decision

管理员接口先应用共用的框架消息排除规则，再进行计数和分页，并随请求页返回过滤后的总数。模型日志页面每页请求 50 条记录，根据总数提供页码、上一页和下一页导航。

写入路径和列表路径共用同一份排除前缀列表，使框架消息既不会进入新记录，也不会出现在历史查询结果中。列表加载器会丢弃已被较新页码请求取代的响应。

桌面端会话 ID 与最近一条有效用户消息的序号共同标识一个用户回合。该回合中的每次上游请求复用同一条审计记录，请求成功或失败后把额度、Token 和耗时累加到回合总数。用户稍后再次发送相同文本时，消息序号不同，因此仍会形成独立记录。没有桌面端会话标识的请求继续按请求记录，因为服务端无法安全判断其回合归属。

审计写入和读取均通过本地用户的产品映射解析账号中心 username。账号中心不可用时保留旧用户名作为回退；列表读取时覆盖历史占位符记录，从而在不重写审计历史的情况下展示当前权威登录名。

列表读取还会兼容合并没有回合 ID 的相邻历史记录：用户、会话、模型和问题均相同且间隔不超过 5 分钟时，界面汇总展示其用量，但数据库中的原始请求记录保持不变。带明确回合 ID 的记录绝不参与该兼容合并。

## Alternatives considered

**在浏览器中对首次响应分页。** 前端分页无法展示服务器没有返回的记录。

**只提供上一页和下一页。** `has-more` 响应可以支持顺序浏览，但无法展示匹配记录总数，也不能直接选择页码。

**按会话和问题文本去重。** 用户可以在同一会话中主动重复发送相同文本，因此文本相同不能定义同一个回合。

## Consequences

管理员可以按稳定的每页 50 条浏览完整的过滤后审计历史。接口会先投影匹配记录再分页，因此总数和页码对应界面实际展示的回合。每个桌面端回合只展示一条汇总用量和账号中心登录名；逐次模型请求明细仍保留在普通调用日志中。
