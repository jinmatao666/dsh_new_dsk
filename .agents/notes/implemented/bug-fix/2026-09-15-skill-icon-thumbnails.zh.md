# Agent Note: 有界技能图标缩略图

Status: implemented

[English](2026-09-15-skill-icon-thumbnails.md) | 中文

## 问题

公开技能列表响应以内联形式携带每个图标。管理员上传的原始光栅图片此前直接存为 data URL，因此少量高分辨率图标就可能超过桌面端 OneAPI 客户端 1 MiB 的响应限制，导致远程技能目录整体不可见。

## 决策

服务端保留内置 glyph 键，以及已经满足限制的 PNG、JPEG、WebP 和 GIF data URL。超限光栅图片会转为保持宽高比的 PNG 缩略图。缩略图的最长边不超过 96 像素，仅在满足 data URL 不超过 48 KiB 的要求时继续缩小。完整解码前，源图片限制为 1600 万个解码像素。不支持或格式错误的值使用内置默认图标。

元数据写入与技能包导入使用同一套规范化逻辑。启动迁移以幂等方式处理现有光栅图标，不推进技能元数据时间戳；随后技能缓存加载压缩后的值。管理页面继续接受不超过 2 MiB 的文件，并说明服务端会生成适合桌面端的缩略图。

## 曾考虑的替代方案

**提高桌面端响应限制。** 这种方案仍会保留数 MiB 的目录响应，并随着技能目录增长再次触发同类问题。

**不向现有桌面端返回自定义图标。** 把所有光栅图片替换为 glyph 可以恢复加载，但会丢失管理员选择的视觉标识。

**只通过独立 URL 提供图标。** 现有桌面端渲染器只把 glyph 键和光栅 data URL 识别为图片。URL 图标需要更新安装包并制定缓存策略，而有界缩略图只需部署服务端即可修复已有安装。

## 后果

当前目录的公开技能元数据会保持在响应失败阈值以内，每张卡片保留所选图片的宽高比、颜色和透明度。大型动态 GIF 会变为静态 PNG 缩略图。无效图片或解码尺寸异常的图片会回退到默认 glyph，不会占用无界内存。
