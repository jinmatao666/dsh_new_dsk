# Agent Note: 对话输入引用的光标间距

Status: implemented

[English](2026-10-21-composer-reference-caret.md) | 中文

## 问题

行内引用胶囊包含不可编辑的图标和可交互的技能按钮。外层行内元素没有独立布局盒时，光标绘制可能与胶囊相交。后续文本分隔空格产生两个相邻方向键停靠点，绝对定位的移除角标则伸入相邻引用。

## 决策

[引用外层](../../../../packages/client/ui-conversation/src/client/input/editor/chip-node.tsx)使用行内块，两侧各预留三像素水平内边距；技能外层在胶囊和移除角标周围预留额外的前后间距。引用布局仅预留视觉空间，不添加文字或可编辑节点。

[键盘映射](../../../../packages/client/ui-conversation/src/client/input/editor/keymap.ts)让折叠光标在一次不带修饰键的水平方向键操作中跨过一个引用及其后的单个 ASCII 空格。连续多个空格、选区手势、带修饰键的方向键和输入法组合输入交给原编辑器处理。剪贴板文本、引用实例标识和提交编码器保持不变。

包含引用的文档到达两端时，不带修饰键的向外方向键停止移动，不进入 WebKit 的辅助装饰节点 DOM。[光标绑定](../../../../packages/client/ui-conversation/src/client/input/editor/chip-caret.ts)为已聚焦、折叠且位于引用外层旁的元素位置选区绘制 CSS 光标。原生文字光标保持不变；失焦、范围选区、只读状态、根元素替换和清理均会移除装饰。WebKit 的辅助换行图片保留 DOM 身份，同时将尺寸和不透明度设为零，避免绘制破图图标且不改变编辑器文字。

## 考虑过的替代方案

**删除分隔空格。** 这会让持久化草稿和剪贴板中的引用标记与后续文字粘连。保留文本分隔既维持这些表示，又不引入另一种节点类型。

**只添加外边距。** 外边距不能消除重复方向键停靠点，脱离文档流的角标也仍然没有预留宽度。原子布局盒与流内按钮同时处理布局和导航。

**插入不可见文字锚点。** 额外字符会产生可编辑位置，并需要从剪贴板、持久化和提交内容中剔除。仅作用于 DOM 的光标装饰不改变这些表示。

## 影响

技能胶囊为移除按钮预留额外宽度，长名称因此更早截断。键盘用户仍有可见的按钮焦点。专项编辑器测试覆盖导航、光标装饰清理及文本不变；Chromium 和 WebKit 检查覆盖连续向外方向键、两种引用类型、输入和删除。macOS WKWebView 仍需发布实机验收，因为 Windows 上运行的 WebKit 无法复现全部原生光标绘制缺陷。修改不增加模型可见内容或网络请求。
