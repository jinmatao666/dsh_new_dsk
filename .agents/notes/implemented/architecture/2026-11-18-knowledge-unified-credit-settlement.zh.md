# Agent Note: 订阅知识库积分使用统一计费任务

Status: implemented

[English](2026-11-18-knowledge-unified-credit-settlement.md) | 中文

## Problem

订阅知识库回执直接扣减账本并发放维护者分成。独立结算绕过统一任务状态，对失败操作和中断的问答响应需要单独处理。

## Decision

[订阅策略决策](../feature/2026-11-12-operations-knowledge-credits.zh.md)保留版本豁免、维护者定价、溯源收费和预览权益。本文负责共用结算实现。

可信 Go 知识库处理函数读取维护者价格，通过统一计费 API 所用的事务实现预留。文件操作在联系 RAGFlow 前预留。问答在执行前预留一份溯源单价，保存完整答案后，在同一事务中对每个不同的引用文件结算。没有引用时释放初始预留。其余引用文件在结算中预留，余额不足时保留已保存的答案供恢复。

数据库保存任务凭据和价格快照。每分钟的恢复任务沿用原任务结算已保存答案。统一过期处理在三十分钟后释放预留。维护者分成复用管理员发放积分的事务和审计回执。消费任务、发放和知识库回执在同一事务中提交。

## Alternatives considered

**调用公开 API 并传入客户端金额。** 当前 HTTP API 要求使用配置的扣分点，并拒绝任意金额。后端读取维护者价格保留了这项限制，也让消费和发放可以共同提交。

**问答前预留整个知识库的全部文件费用。** 实际引用在问答完成后才确定。预留整个库会要求用户为无关文件准备积分，改变约定的按溯源文件收费规则。

## Consequences

问答生成后可能需要追加积分。答案在结算成功后开放，恢复过程沿用原结果，过期任务保持原终态。单文件价格遵循统一的一千积分上限。旧回执继续有效，桌面流水避免把新任务消费重复计入。
