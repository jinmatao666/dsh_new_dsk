# Agent Note: Dynamic skill release management

Status: implemented

[English](2026-09-07-dynamic-skill-release-management.md) | 中文

## Problem

技能说明、脚本和业务接口只能随服务端镜像与桌面端静态元数据投影一起变更。服务启动还会用签入文件覆盖后台维护内容，导致任何技能生命周期操作都需要重新构建产品产物。

## Decision

服务端将每个完整的平台技能保存为不可变的 `skill_releases` 记录，并在 `skills` 上保存当前已发布版本。版本号只在同一技能内唯一，因此不同技能可以发布相同的语义化版本。导入 ZIP 时，服务端会校验根目录 UTF-8 文件、匹配的 kebab-case 名称、完整的清单文件列表、普通相对路径、大小限制、重复路径与 SHA-256 摘要，然后创建草稿；服务端不会执行上传的文件。发布和回滚以事务方式选择一个版本，将该版本的包同步到既有的提示词注入缓存字段，并立即刷新缓存，不重启容器。下架会让技能不再出现在公开市场中，但不会删除桌面端已安装目录。

管理接口中的导入、校验、版本历史、发布、回滚和下架仅管理员可用。全局管理员操作日志中间件记录操作者、路由和时间。公开元数据与下载接口只提供已发布技能。桌面端只有在原子安装成功后才增加下载计数。

桌面端市场只从已登录的服务端读取已发布元数据。它下载完整文件集合与服务端 SHA-256，在原生进程中校验规范化摘要、校验清单，再原子替换 `.dsh/skills/<slug>`。本地提供者通知会清空斜杠菜单缓存，因此当前对话下一次输入 `/` 就能发现安装、更新或移除。个人技能仍是平台 API 之外的本地带标记目录。展示 Mock 在目录较少时继续保留，但会标记为仅演示、不可安装、不计数、不进入已安装列表；已发布技能使用同一 slug 时 Mock 自动隐藏。

技能包自行保存脚本、接口路径、URL 配置要求、模板、参考资料和领域数据解析逻辑。平台只理解通用清单元数据和可选配置声明。GIS 示例技能要求提供 `DSH_GIS_SERVICE_URL` 或显式脚本参数，不再包含公网地址回退。服务端构建会把签入的示例包排除在运行时资源之外。已有的已发布 `skills` 记录仅迁移一次为版本记录，启动时不再覆盖。

本记录取代[桌面技能安装与依赖授权](../feature/2026-09-01-desktop-skill-install-and-dependency-grant.md)中服务端目录与离线内置包的部分；其中本地原子安装、个人技能、依赖授权、交付物和桌面运行时的决定仍然有效。

## Alternatives considered

**只在 `skills` 保存可变包内容** — 不采用。这样无法保留草稿、发布历史和可回滚版本。

**将上传包存入 Web 文件系统** — 不采用。容器替换会丢失本地文件，也会增加备份和审计复杂度。第一阶段使用数据库保存受大小限制的包，同时保持未来可切换对象存储的 API。

**校验时执行上传脚本** — 不采用。校验只检查包结构和元数据；实际执行属于桌面主机的常规权限模型。

**立即删除市场 Mock** — 不采用。在正式目录数量足够之前，它们仍可作为展示兜底，但不能被误认为可安装技能。

## Consequences

管理员可导入第四个技能、校验、发布、更新、下架或回到历史版本，无需重新构建服务端镜像或桌面安装包。平台能力首次部署仍需要构建这两个产物，以包含 API 与原生 SHA-256 校验器。新部署不会再初始化内置技能；管理员通过版本工作流导入需要的包。

数据库会随每个版本的文件大小和数量增长。导入限制为压缩包 10 MiB、解压后 30 MiB、单文件 5 MiB、最多 200 个文件和八层路径。未来迁移对象存储时必须保留版本 ID、版本号、SHA-256 和下载接口字段。

## Verification

控制器测试覆盖完整技能包通过校验、路径逃逸和名称不匹配被拒绝。控制器与模型包编译、市场类型检查和桌面端 Rust 检查覆盖版本模型、API 调用方、原生摘要校验与原子安装路径。
