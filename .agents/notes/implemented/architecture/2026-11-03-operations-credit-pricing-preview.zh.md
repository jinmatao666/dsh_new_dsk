# Agent Note: Operations model credit settlement

Status: implemented

[English](2026-11-03-operations-credit-pricing-preview.md) | 中文

## Problem

管理员需要独立输入、输出倍率、单独的缓存价格，以及与实际余额扣减一致的消费明细。原补全倍率表示输出相对输入的倍数，缓存用量之前仅用于观测。

## Decision

运营版将 `creditPricingBase` 保存在 `SystemDeploymentSettings`，默认 1× 对应每千 Token 一积分。模型编辑将独立输入、输出、缓存命中、缓存创建倍率保存至 `ModelCreditPricing`；只读价格等于基准乘倍率。缺少缓存倍率时使用输入倍率。旧预览选项不会静默启用扣费：管理员需保存模型至正式计费选项。

每个模型价格条目中的可选 `display` 字段控制桌面参考倍率。省略时取输入、输出倍率的算术平均值；显式设置的值（包括零）不会随计费倍率变化。模型编辑支持恢复自动默认值。登录后的模型元数据通过 `display_multiplier`，经过受管提供方及共享模型目录传到选择器，在模型名旁显示并提示仅供参考。模型 ID 和实际结算价格与此展示字段独立。

文本转发在访问上游前固定价格快照。普通输入扣除缓存命中、创建 Token，四类用量分别乘对应倍率、统一基准和分组倍率。十进制有理数运算在合计后仅向上取整一次至内部额度单位。政务版及未配置正式价格的模型沿用原有结算。本次覆盖按 Token 计费的文本转发，不包含独立计费的图像、音频服务或外部用量上报。

个人预扣和结算在同一数据库事务内更新用户账本及令牌，拒绝余额不足，并将退款退回原账本行且不延长有效期。预扣不假定缓存优惠。上游失败退回预扣；实际用量超过预扣且补扣失败时，消费明细展示保留的预扣及待核对状态，不会显示全部结算成功。这是请求内结算，不包含服务器崩溃后的持久预扣恢复任务。

消费日志保存价格快照、互斥用量、会话和实际扣分，即使关闭普通消费日志也保留这些记录。模型日志中仅管理员可见的“积分明细”支持服务端筛选、分页和快照计算详情。无快照的旧日志展示原始内部额度，不虚构历史价格。标准 OpenAI 用量详情及 DeepSeek 缓存命中后备字段提供缓存用量；Anthropic 将单独报告的缓存用量加入输入总数后统一处理。上游未提供缓存用量时不计算缓存优惠。

运营版设置同时保存 `creditRewards`：注册与登录的独立开关、1 至 1,000,000 的整数赠送积分，以及 1 至 3,650 的整数登录周期 `intervalDays`。缺少规则时默认关闭，注册赠送默认 2,000 积分，登录默认每天 100 积分。登录规则设计为达到周期后首次登录发放，以上次发放日期起算，未登录不补发；不引入有效期或活动起止日期。此阶段仅配置规则，尚未接入自动发放。前后端均拒绝显式无效规则。保存成功后，在现有后台操作日志的通用设置快照之前记录赠送规则修改前后的值，避免长配置截断导致丢失。现有审计仍异步写入，不与配置保存构成同一事务。数据库配置写入失败会返回错误，不再修改内存中的生效配置或误报保存成功。

## Alternatives considered

**全局修改旧倍率。** 输入为零时无法表示独立输出价格，且其他服务仍使用旧倍率表，因此不采用。

**缓存用量再按普通输入收费。** 会对命中缓存重复扣费，因此用量必须互斥，异常总量进入退款路径。

**每次请求取整为一积分。** 会使短请求收费过高，因此只对内部额度合计值向上取整。

## Consequences

保存的正式价格用于后续请求，历史快照不变。本地 SQLite 集成测试覆盖实际转发 HTTP 成功与失败、余额与日志一致性、余额不足及退款。定向测试覆盖缓存算式、快照稳定性、Anthropic 流式与 JSON 用量归一化以及明细接口和页面。浏览器截图使用示例接口数据，尚未用生产凭据验证真实上游扣费。套餐、积分发放及定价盈利测算仍是独立工作。
