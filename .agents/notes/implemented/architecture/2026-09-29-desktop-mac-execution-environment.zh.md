# Agent Note: 桌面 Mac 执行环境与已记录成果链接

Status: implemented

[English](2026-09-29-desktop-mac-execution-environment.md) | 中文

## 问题

Mac 桌面实测日志显示，直接调用 Node 时找不到随包运行时，Python 安装及缓存写入在工作区写入模式下被拒绝。模型生成的本地 URI 即使对应成功技能结果已记录的真实成果，也可能表现为不可点击链接。

## 决策

产品壳在 `sidecar_environment.rs` 中持有 macOS PATH 和 Python 缓存配置。它保留继承的宿主临时目录，将随包 Node 放到 PATH 首位，保留已有工具路径并补充 Homebrew 目录。Python 缓存位于按产品区分的宿主临时私有目录，现有沙箱策略已允许该区域。已有目录必须是真实目录，所有者与应用数据目录一致，且没有组或其他用户权限。Windows 和 Linux 的启动环境设置保持不变。

产品 UI 持有技能结果及路径标记。通用 Markdown 渲染器对已结束输出的非 Web 链接复用现有的可选文件提及解析器。URI 形式的引用只解析到完整路径精确匹配的已记录成果；不授权新协议跳转，也不根据链接标签猜测文件。官方包不包含产品协议。

## 考虑的替代方案

**允许应用数据目录写入或关闭沙箱。** 这会把凭据和设置暴露给任务命令。把 Python 缓存放在现有临时区域的允许范围内，可保留官方策略和只读行为。

**修改 Windows 技能脚本或在桌面重写 GIS 技能。** Windows 已经正常，技能入口归平台技能维护者负责。桌面修复不重写其业务逻辑。

**允许任意本地 URL 协议。** 模型输出不可信。使用已记录成果身份和现有文件打开能力，而不是执行模型生成的 URL。

## 影响

宿主临时缓存可复用，但可能被系统清理。缺失 Python、FFmpeg 或技能依赖仍需安装或技能侧适配；桌面不下载任意二进制，也不静默扩大权限。技能报告的音频时长及事实结果质量仍由技能和模型负责。macOS 沙箱、Homebrew 工具发现和安装版文件打开仍需实机验收；Windows 测试覆盖不变的环境设置及跨平台成果引用。
