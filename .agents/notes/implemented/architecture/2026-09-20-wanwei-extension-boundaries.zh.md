# Agent Note: 万维扩展边界

Status: implemented

[English](2026-09-20-wanwei-extension-boundaries.md) | 中文

## 问题

官方 DSH 组件内部的私有业务协议和桌面命令使上游更新需要反复迁移产品功能。仅移动文件不能消除这一依赖。

## 决策

官方浏览器包提供不含产品语义的平台动作注册表和成果扩展注册表。产品外壳通过注册表提供原生目录打开、原生文件保存、额外成果解析和成果展示组件。

万维层拥有 Tauri 命令映射、`WANWEI_RESULT` 解析、分析成果展示、OneAPI 视觉 Provider 和技能市场。这些实现位于 `packages/wanwei`，只通过万维 Bundle 进入应用。

这一结构使官方 Workspace、Session 导出和 Deliverables 包在没有桌面 Provider 时仍可使用。缺少 Provider 时，可选动作不显示或回退到浏览器下载；官方运行时成果识别也不再依赖私有协议标记。

私有产品包声明 `dsh.release: false` 和 `private: true`，且不包含 `publishConfig`。通用工作区和发布检查将这些包排除在官方发布系列之外，并拒绝已发布官方包反向依赖私有层。这条边界不依赖产品名称白名单。

## 考虑过的替代方案

**把私有行为保留在官方组件中。** 这可以继续直接访问组件内部对象，但会使上游组件更新依赖万维业务协议和桌面命令映射。

**要求官方文件零修改。** 这无需维护兼容补丁清单，但可能迫使实现使用不受支持的接入方式或移除既有行为。当官方组件缺少受支持的注册机制时，保留通用扩展点。

## 影响

更新上游时必须保留这两个通用注册表，或者替换为上游提供的等价扩展点。产品协议和原生命令的变化继续留在万维包中。维护者仍需核对少量通用官方修改；这种分离不承诺上游升级完全没有冲突。
