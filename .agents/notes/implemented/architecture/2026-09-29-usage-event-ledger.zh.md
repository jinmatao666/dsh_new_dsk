# Agent Note：技能与专家使用事件台账

Status: implemented

[English](2026-09-29-usage-event-ledger.md) | 中文

## 问题

管理员需要按人员统计技能和专家使用量，而打开专家页签、未发送技能消息不应算作使用。

## 决策

产品 Host 观察官方技能注入器已解析的 `user/message` 和每次名为 `skill` 的 `tool/call`，用稳定事件编号分别上报 `user_explicit` 和 `model_auto`。独立专家网站在 `worker.submit` 后上报；提供方凭据确定专家，兑换票据所得用户编号确定人员。OneAPI 自动迁移事件台账，向后台四个页签提供总数、Top 10、部门分组和每日数据。组织归属接入前，部门字段可为空。

## 曾考虑的方案

**每轮对话只计一次：**同一轮内模型可能多次调用同一技能，因此不采用。

**打开专家页签即计数：**浏览专家资料并不代表开始执行任务，因此不采用。

## 结果

只有相同事件编号才去重。桌面端把待上报技能事件绑定到采集时的令牌，运行期间重试，但退出后不保留离线待发队列。专家任务上报最多重试三次，不阻断已受理任务。

## 测试

Host 提取测试覆盖重复调用、重试编号和插件注入消息。六个独立专家网站各自验证提供方上报内容，并运行任务和身份测试。OneAPI 控制器测试覆盖鉴权、人员归属、去重与分组查询；后台页面完成生产构建。
