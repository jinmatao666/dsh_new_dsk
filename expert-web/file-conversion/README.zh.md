# 文件转换专家（开发中）

任务轮询仅在首次返回或任务数据变化时重绘页面；准备表单打开期间只更新缓存，不替换当前表单。较早请求的响应不能覆盖较新成功请求的数据；手动结果刷新使用相同的顺序保护。

[English](README.md) | 中文

任务、预览或成果请求返回 HTTP 401 时，工作台锁定并清除任务和材料缓存；迟到响应不能恢复页面。下载过程中登录失效会取消成果读取，不再调用原生保存。需关闭 Tab，从桌面专家库重新打开以交换新票据；这些前端检查不撤销提供方已经接收的任务。

Compose 固定容器监听端口，使其与仅绑定本机的端口映射一致；修改 `.env` 中的 `PORT` 不会改变该端口。如需其他本机代理端口，修改 `ports` 的宿主机端口；公网 HTTPS 地址通过 `EXPERT_PUBLIC_URL` 配置。

## 独立迁出验证

网站公网地址与平台票据核验地址支持 HTTP 和 HTTPS。仍建议 HTTPS：HTTP 会使票据、提供方凭据、Cookie 和任务数据面临窃听或篡改。来源检查仍包含协议、域名和端口，核验拒绝重定向。从只支持 HTTPS 的代码升级时，除重部署网站外，还需重新构建平台镜像和桌面安装包。原有 HTTPS 代理示例仍可使用；此前只支持 HTTPS 的表述以此项为准，并不意味着 HTTP 已有加密保护。

运维可执行 `python deployment.py` 检查配置和本地处理依赖；只输出检查名及通过状态，不打印密钥或接口地址。`/healthz` 验证 HTTP 与数据库可用，`/readyz` 检查所有已提供功能的必要配置，未配置返回 503；后者不是远程服务真实连通性测试。Dockerfile 配置了存活检查。

在已更新的桌面专家 Tab 中，成果下载通过 `save_expert_artifact` 打开原生“另存为”窗口，由用户选择目标路径和确认覆盖。网站不能提供本机路径。接口校验成果字节（最大 128 MB）、文件名和原始扩展名，返回已保存路径，取消返回 null。普通浏览器使用浏览器下载；三平台桌面交互仍待验收。

在本目录执行 `python verify_portability.py`。脚本只复制本专家目录到临时位置，排除本地数据和凭据，再创建全新虚拟环境、安装自身依赖并执行 Python/Node 测试，不读取 DSH 根目录或其他专家代码。Node.js 需要已安装。

`python verify_portability.py --deployment` 还要求 Docker Compose 配置校验和镜像构建；缺少 Docker 会明确失败，不将未执行的部署检查算作通过。容器实际启动、HTTPS、真实业务接口和桌面同窗联调仍须在目标环境验收。

工作台已接入自有旧版图标和背景，任务列表可打开详情，成果文件独立汇总。原始文件名仅保存为任务元数据；服务器上传路径始终使用内部编号。已有数据库会自动增加文件名字段，不复写旧记录；历史记录没有原名时显示原存储名称。视觉逐状态验收仍未完成。

本目录完全独立，不引用 DSH、OneAPI 或其他专家源码。已有工作台原型、HTTP 服务及真实处理引擎，生产资源隔离与旧版视觉验收尚未完成，不应正式上架。

## 服务运行

图片转 PDF 和图片优化表单使用临时对象 URL 在本地预览已选图片；删除文件或离开页面时释放 URL。预览不上传文件，提交时才把所选文件发送到本专家服务。五类工具均提供可用键盘操作的上传按钮、文件排序和移除控件。

提交前的核对页显示任务名称、按顺序排列的输入文件、处理参数和预计成果类型。预计成果说明请求的操作，而非成功结果；只有服务器完成的任务才展示实际成果文件。返回修改保留所选文件和参数。

成果页保留流程步骤、任务名称、创建时间和输入数量。单一旧版式结果容器包含服务器返回的状态和实际成果列表；输入参数位于下方可折叠的任务详情中。未完成或失败任务没有下载链接。与旧版本地工作台不同，本服务不向桌面文件管理器暴露服务器任务目录；用户下载已发布的成果。

空记录和空成果页提供新建任务入口，按旧版行为打开首个工具 Word 转 PDF。记录行标明任务、创建时间、输入数量、工具和服务器返回的状态。

配置 `.env.example` 所列环境变量后运行 `python server.py`。程序不会自动加载 `.env`，请由进程管理器注入。只允许一个服务进程打开数据目录；它拥有队列，重启时将未完成任务标记为失败。监听默认 `127.0.0.1:4301`，必须由 HTTPS 反向代理提供公开入口；代理须限制请求体大小为 45 MB，并限制并发上传和请求速率。本地测试使用注入的票据核验函数，不是生产登录后门。

取消会立即隐藏任务成果并终止本地转换进程树。Linux 超时时也会杀死整个转换进程组；Windows 使用 taskkill 清理进程树。Linux 子进程限制 1 GB 地址空间、单文件 128 MB、CPU 120 秒，容器再限制 1.5 GB 内存和 2 CPU。完成/失败/取消任务默认保留 30 天，启动及新任务提交前清理，天数由 EXPERT_RETENTION_DAYS 设置（1–365）。运维仍须配置数据卷容量监控和备份；尚无每用户总容量配额。

## 容器部署（未在本机实跑）

将 `.env.example` 复制为 `.env` 并配置真实 HTTPS 地址和服务端凭据，执行 `docker compose up --build -d`。独立目录中的 Dockerfile 安装 LibreOffice 与中文字体，非 root 运行；compose 只绑定本机端口，公开入口使用 `nginx.conf.example` 中的 HTTPS 代理配置。必须在目标服务器检查 `docker compose config`、容器日志、真实 Word 转换及备份恢复。首次发布前应将基础镜像固定到已审核 digest。

`test_office` 包含真实 DOCX 转 PDF 测试；没有 soffice 时明确跳过，不作为成功验证。在装有 LibreOffice 的环境执行测试，生成 PDF 后检查正文文字。

`processors.convert` 只能由服务端传入自己拥有的上传路径和新任务输出目录，不允许直接接受浏览器传来的本地路径。失败时可能留下部分文件；未来任务服务须标记失败并只发布成功任务的产物。不得将底层异常、服务器路径或提供方密钥返回网页。

Word 转 PDF 将使用独立服务器的 LibreOffice，而不是访问用户本机 Word/WPS。这项部署差异须在网页与部署说明中明确。PyMuPDF 的授权及商用部署许可也须在生产部署前确认。
左栏四个导航图标是旧版专家原始 PNG 的本站独立副本。使用说明采用顶部介绍和四张步骤卡片，保留本专家的输入限制与复核要求；运行时不引用其他专家的资源或样式。
