运行中任务详情按服务端创建时间显示已等待时长，每秒更新，不重绘结果页面。这是等待时间，不是完成时间预测或百分比；页面关闭或登录失效时停止计时。开启减少动态效果时，进度图标保持静态。

任务、预览或成果请求返回 HTTP 401 时，工作台锁定并清除任务和材料缓存；迟到响应不能恢复页面。下载过程中登录失效会取消成果读取，不再调用原生保存。需关闭 Tab，从桌面专家库重新打开以交换新票据；这些前端检查不撤销提供方已经接收的任务。

模型解读沿用旧版回答布局：按实际 Markdown 标题组织可读段落，完整回答经过转义后保留在展开区域。文件清单和原始数据段落只在完整回答中保留，不混入提取的结论。模型输出不能注入 HTML 或执行脚本。

`interpretation.py` 独立拥有本专家的 HTTPS 模型适配器和领域解读规则。任务使用本次完整 GIS 记录生成解读，在 Word、结果 JSON 和网页中单独展示模型正文，不改变服务统计。在本专家服务器配置 `EXPERT_MODEL_URL`、`EXPERT_MODEL` 和 `EXPERT_MODEL_KEY`。缺少配置、输入超限、空响应或输出截断均在报告发布前使任务失败。就绪检查要求同时配置 GIS 和模型。本地协议及工作进程测试使用明确的模型替身，不能证明生产模型质量或完整视觉一致性。

Compose 固定容器监听端口，使其与仅绑定本机的端口映射一致；修改 `.env` 中的 `PORT` 不会改变该端口。如需其他本机代理端口，修改 `ports` 的宿主机端口；公网 HTTPS 地址通过 `EXPERT_PUBLIC_URL` 配置。

## 独立迁出验证

网站公网地址与平台票据核验地址支持 HTTP 和 HTTPS。仍建议 HTTPS：HTTP 会使票据、提供方凭据、Cookie 和任务数据面临窃听或篡改。来源检查仍包含协议、域名和端口，核验拒绝重定向。从只支持 HTTPS 的代码升级时，除重部署网站外，还需重新构建平台镜像和桌面安装包。原有 HTTPS 代理示例仍可使用；此前只支持 HTTPS 的表述以此项为准，并不意味着 HTTP 已有加密保护。

同一任务结果刷新保留详情展开和阅读位置，打开另一任务时详情默认折叠。准备页将高级选项放在文件列表下方，右侧说明数据要求与交付物；说明不代表成果已经生成或坐标已经转换。

准备说明卡内的 SVG 等高线复制自旧版 TerrainIllustration，由本专家独立持有，仅作装饰，对辅助技术隐藏，不代表上传范围或分析结果。

结果页将状态横幅、服务数据及实际成果卡片与任务信息侧栏分开，窄窗口纵向排布。只有成功任务展示下载；失败和取消明确提示本次没有可展示结果，并提供重新创建入口。

“刷新结果”与自动轮询并存，成功读取当前用户任务后清除选中任务的预览缓存，再读取实际成果；请求中阻止重复点击。刷新失败保留现有数据并允许重试。

运维可执行 `python deployment.py` 检查配置和本地处理依赖；只输出检查名及通过状态，不打印密钥或接口地址。`/healthz` 验证 HTTP 与数据库可用，`/readyz` 检查所有已提供功能的必要配置，未配置返回 503；后者不是远程服务真实连通性测试。Dockerfile 配置了存活检查。

在已更新的桌面专家 Tab 中，成果下载通过 `save_expert_artifact` 原生接口写入用户下载目录，最大 128 MB，不接受本机路径且不覆盖同名文件；普通浏览器继续使用浏览器下载。此链路有前端字节转发和原生文件保存测试，但三平台实际点击下载仍待验收。

在本目录执行 `python verify_portability.py`。脚本只复制本专家目录到临时位置，排除本地数据和凭据，再创建全新虚拟环境、安装自身依赖并执行 Python/Node 测试，不读取 DSH 根目录或其他专家代码。Node.js 需要已安装。

`python verify_portability.py --deployment` 还要求 Docker Compose 配置校验和镜像构建；缺少 Docker 会明确失败，不将未执行的部署检查算作通过。容器实际启动、HTTPS、真实业务接口和桌面同窗联调仍须在目标环境验收。

工作台已接入自有旧版图标和背景，任务列表可打开详情，成果文件独立汇总。原始文件名仅保存为任务元数据；服务器上传路径始终使用内部编号。已有数据库会自动增加文件名字段，不复写旧记录；历史记录没有原名时显示原存储名称。视觉逐状态验收仍未完成。

本目录独立拥有网页工作台、身份会话、SQLite 持久任务、范围解析、GIS 服务适配和成果生成，不引用 DSH、OneAPI 或其他专家源码。真实 GIS 服务、容器运行、旧版视觉和桌面嵌入尚未验收，不可正式上架。

支持单个 GeoJSON/JSON、Shape ZIP 或一个完整 Shape 文件组（.shp、.shx、.dbf，可附 .prj）。仅接受面范围，验证闭环、有限数值、记录边界及数量；ZIP 在内存中读取，不解压到用户指定路径。最多 10 万坐标点，ZIP 解压总大小不超过 64 MB。当前不转换坐标系，使用原始坐标；用户和部署人员必须核对分析服务所需坐标参考。不能因为上传成功就推断坐标正确。

GIS 地址由服务端 EXPERT_GIS_URL 显式配置到完整分析接口，不内置旧生产地址，也不允许网页提供任意请求地址。允许现有内部 HTTP 服务，但运维必须保障可信网络；公开网页入口必须为 HTTPS。接口为 /Analysis.svc/SanDXzAnalysis，默认三调年度 2024，其他开关与旧版协议一致。

成功处理生成真实 Word 报告、Excel 明细、接口原始 JSON 和中文结果 JSON。结果页读取本次任务的中文 JSON，在页面限量预览各数据集，完整文件仍可下载。报告只解读已映射字段，未映射项保存在原始响应并明确提示待核对，不编造结论。各图层面积口径独立，面积单位沿用服务返回原值，不擅自换算。空数据集不能自动解释为无风险。

在本目录创建 Python 3.13 虚拟环境，安装 requirements.txt，然后执行 `python -m unittest -v test_geometry test_analysis`。本地测试使用明确的服务响应替身，不证明真实服务可访问、响应兼容或空间结论正确。上线前必须以授权测试范围完成真实 GIS 请求，复核原始结果、单位、坐标系与 Office 成果。

尚缺：旧版资源与专用工作台还原、完整字段映射复核、真实 GIS 端到端任务、中文报告渲染、容器实际运行及三平台桌面同窗 Tab 验收。

## 服务和部署

由进程管理器注入 .env.example 所列变量后运行 `python server.py`。程序不自动读取 .env，单实例独占数据目录。容器配置位于本目录；配置 .env 后执行 `docker compose up --build -d`，通过 nginx.conf.example 的 HTTPS 代理公开访问。基础镜像发布前固定到审核过的 digest。本机没有 Docker，配置尚未构建实跑。

执行 `python -m unittest -v test_geometry test_analysis test_server`。HTTP 测试启动独立本地协议测试服务，经真实网络请求、转换子进程和文件下载验证 Word 成果；这不等于已连接生产 GIS 服务。未配置地址时任务明确失败，不生成演示结果。网页请求不能指定服务地址。

任务最多 30 文件、合计 32 MB，默认终态任务保留 30 天。取消不发布成果，并终止本地工作进程树；远程 GIS 服务已经接收的请求仍可能继续在服务端运行。Linux 超时也会回收整个进程组。部署须配置磁盘监控、容量限制、备份和请求速率限制。
左栏四个导航图标是旧版专家原始 PNG 的本站独立副本。使用说明采用顶部介绍和四张步骤卡片，保留本专家的输入限制与复核要求；运行时不引用其他专家的资源或样式。
