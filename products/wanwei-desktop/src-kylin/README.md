# Kylin desktop shell

English | [中文](README.zh.md)

This Linux shell compiles the business commands from [src-tauri](../src-tauri/src/lib.rs) against Tauri 1 and embeds expert WebKit views inside the main GTK window. Windows, macOS and modern Linux use the existing Tauri 2 shell. Business pages, APIs, skills and the Node sidecar have one source; GTK view management and the native transport require separate platform maintenance. New native commands need registration in both shells.

The desktop preview workflow defaults build_scope to all. To build only Kylin without registering a workflow on main, open the existing Wanwei Buddy desktop entry, select the new-version workflow branch, and choose build_scope=kylin. This skips the standard desktop matrix and always enables Kylin; the shared official-composition verification still runs. Release publication requires the full desktop matrix and is skipped in Kylin-only mode.

The container trusts only its mounted checkout directory in the persistent Git configuration and verifies HEAD before dependency installation. This lets subsequent shell steps read source metadata despite the checkout action using a temporary HOME.

The [desktop preview workflow](../../../.github/workflows/wanwei-desktop-preview.yml) enables the Kylin build with its default-on build_kylin input. The [shared Kylin workflow](../../../.github/workflows/wanwei-kylin.yml) implements the compatibility jobs called by that entry. Both architectures build in Ubuntu 20.04 containers. Native GTK linking and graphical tests require Linux runners for this user-authorized compatibility build, despite the repository's general Windows runner preference.

Choose the wanwei-buddy-VERSION-kylin-arm64-deb artifact for the supplied Kylin aarch64 machine. Its installer filenames include -kylin, keeping them distinct from modern Linux artifacts. DEB declares system dependencies; AppImage includes additional libraries but still has a system ABI floor. Both formats are extracted and audited before upload. The audit rejects wrong architectures, missing libraries, WebKit 4.1 or libsoup 3, GLIBC above 2.31, GLIBCXX above 3.4.28 and CXXABI above 1.3.12.

DEB and AppImage build, audit and upload independently, with artifact names ending in -deb and -appimage. DEB uploads before AppImage starts, so an AppImage failure leaves an audited DEB available for testing while the job remains failed. The evidence artifact includes separate build logs, format-specific audit reports and the generated AppImage script when available. Builds use verbose Tauri logging and preserve the packager exit code through log capture. Only the known ARM64 architecture-detection error retries the generated final packaging command with the legacy arm_aarch64 alias; other errors remain fatal, and the resulting installer still requires the full audit.

Kylin updates use replacement installers. Tauri 2 automatic update bundles are not offered by this shell. Closing the main window hides it; the tray menu exits and stops the sidecar.

The Kylin shell defaults WEBKIT_DISABLE_COMPOSITING_MODE and LIBGL_ALWAYS_SOFTWARE to 1 before GTK starts, while preserving explicit environment overrides. Software rendering avoids the blank window observed on the target machine but can increase CPU use. The expert overlay passes empty-space pointer events to the main page while embedded experts retain input. Native commands are available inside the desktop WebViews; opening the loopback address in a regular browser does not provide desktop expert or skill installation commands.

## Verification

Kylin staging rewrites the GFM email autolink expression only in its copied JavaScript artifacts. Its equivalent matcher checks the preceding Unicode character without lookbehind, preserving captures and match positions; JavaScript source maps are regenerated. The shared runtime and business sources remain untouched. The graphical probe renders production Markdown components in streaming and settled states, covering Chinese replies, emphasis, links, email, tables, code and math. An unadapted artifact reproduces the WebKitGTK 2.38.6 regular-expression exception even for a plain greeting.

The Kylin shell injects [browser compatibility](browser-compat.js) at document start in its trusted main and expert views. It supplies AbortSignal.any only when missing, retains native signals and abort reasons, and releases subscriptions on cancellation or garbage collection. Shared business sources and the Tauri 2 startup path remain unchanged. The shared product bootstrap supplies JavaScript standard-library methods through core-js; browser Web APIs require separate checks. The graphical smoke executes the production Gateway supervisor through delivery, restart and disposal, checks native fetch cancellation, and calls the shared skill and first-send workspace clients. These keyless checks do not establish authenticated model-list or provider-chat success.

The WSL Ubuntu 20.04 x86_64 validation passes compilation, Rust business tests and a real WebKit smoke with two embedded experts, native file reads, expert command authorization, ticket bootstrap, geometry shrinking, visibility, JavaScript state preservation, close and logout. Bridge tests cover origin and document isolation, error propagation and timeouts. The complete staged sidecar passes startup, authentication exchange and clean shutdown on the native Linux filesystem. The full x64 DEB builds and passes dependency metadata and extracted-payload audits covering 11 ELF files. Local AppImage bundling remains unverified because a helper download is blocked. The smoke uses local test pages with Xvfb and software rendering; it does not establish real expert login, installed-device focus/input, GPU, Wayland or ARM64 compatibility. Release and target-device tests must cover those remaining conditions. The [decision record](../../../.agents/notes/proposed/architecture/2026-11-16-kylin-desktop-shell-isolation.md) describes the remaining acceptance conditions.
