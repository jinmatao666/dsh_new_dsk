# 地质条件分析

按操作系统选择本技能目录中的 `scripts/invoke.ps1`（Windows）或 `scripts/invoke.py`（macOS）调用地质条件分析服务。需要接口字段说明时读取 `references/api.md`。

## 输入

- 当前工作区中的 Polygon 或 MultiPolygon GeoJSON、`.shp` 文件、完整 Shape 文件夹，或包含完整 Shape 文件的 ZIP。
- Shape 数据集至少需要同名的 `.shp`、`.shx`、`.dbf` 文件；`.prj` 用于自动识别坐标系，存在 `.cpg` 时将其随数据集一并保留。
- 优先读取 `.prj` 和 `.dbf` 字段。用户只给出一个 ZIP、文件夹或 `.shp` 时直接使用；工作区存在多个候选数据集且用户未指定时才询问。
- 只有无法从 `.prj` 或用户说明确定坐标系时才询问用户，不得混用经纬度与投影坐标。
- 可选分区名称字段，默认“分区名称”。

## 执行

1. 当前已是 Workspace Write 时直接运行脚本，不得再次申请 `workspace-write` 提权；只有命令执行器单独要求外部网络授权时才等待用户确认。完全访问模式按当前授权直接执行。
2. 按下方操作系统规则选择入口；Windows 使用 PowerShell 运行：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File <技能目录>/scripts/invoke.ps1 -InputPath <GeoJSON、.shp、ZIP 或文件夹路径> -OutputDirectory <当前工作区>`。
3. 用户指定字段时追加 `-YfxFieldName <字段名>`；运维指定其他服务地址时追加 `-BaseUrl <地址>`。
4. 技能安装目录是只读程序资源。脚本执行失败时报告原始错误，不得使用 Edit、Write 或命令改写技能目录中的任何文件。
5. 脚本仅临时解压和转换 Shape 数据，结束后清理过程文件；Excel 与 Word 使用“输入文件名 + 分析简称 + 短时间戳”的中文名称，例如 `地块1_地质_0905-103811.xlsx`，不覆盖已有文件。原始 JSON、Markdown 底稿和对话分析视图用于追溯，不作为普通产物展示。Excel 分析表生成后会尝试用系统默认表格应用打开。

## 交付

- 正式成果仅包含：Word 分析报告和 Excel 明细表。
- JSON、Markdown、转写文本、提取文本、索引、处理日志和临时文件均为内部文件，不进入成果列表，不在最终回复中列作交付。不得默认额外生成 ZIP。
- 仅使用成功返回的 `artifacts` 中真实存在的路径展示成果；失败时说明原因，不猜测文件名、不自行拼接链接。工作台使用的分析视图 JSON 必须内部保留。

## 操作系统与运行前检查

- Windows：保留现有 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File <技能目录>/scripts/invoke.ps1` 入口及其业务参数。
- macOS：使用 `python3 "<技能目录>/scripts/invoke.py" --check` 检查环境，然后使用同一入口运行。禁止在 Mac 调用 `powershell.exe`，禁止模型临时重写数据解析、接口请求或报告生成脚本。
- GIS 的 macOS 入口仅使用 Python 3.9+ 标准库，不需要 PowerShell 7 或 Python GIS 库；可直接使用系统 Python 3.9，也可使用桌面端打包的更新版本。执行参数保持原样，例如 `python3 "<技能目录>/scripts/invoke.py" -InputPath "<输入路径>" -OutputDirectory "<输出目录>"`。解释器不可用时应明确报错，不要临时改写业务脚本。
- 检查失败、路径不可用、依赖安装或输出目录被沙箱拒绝时明确报错并停止；由桌面端处理工具路径、审批与成果链接展示，不静默绕过，不自动下载替代工具。
- 执行必须等待结束，依据退出码及最终 `WANWEI_RESULT` 判断状态；`--check` 仅代表环境检查，不代表业务执行成功。

## 分析与报告要求

- Excel 分析表，包含“结果汇总”“专业分析”“接口明细”工作表，以结构化表格呈现研判结论和全部实际返回字段。
- Word 专业分析报告按“项目与数据概况、核心分析结论、专业研判、实施建议与结论、数据来源与使用限制”组织正文。正文只保留可读的坐标系名称和关键统计结果；完整投影 WKT、属性字段代码和原始接口 JSON 仅用于追溯，不进入报告正文。
- 分析底稿仅内部留存。读取 `references/api.md` 与结果后，在对话中用中文给出分析。表格由结果卡片呈现，不再重复打印 Markdown 表格。综合结论必须把地质环境条件和灾害易发性转化为工程影响，不得只复述等级或面积。只把 Excel 与 Word 作为主要交付文件列出。Excel 或 Word 任一文件未生成时，必须明确报告交付失败；接口名、字段代码和文件名保留原文。

最终回复必须采用清晰的 Markdown 层级，依次使用 `## 综合结论`、`## 关键发现`、`## 项目影响与建议`、`## 主要交付文件` 四个二级标题。综合结论写成一段不超过 180 字的结论性文字；关键发现和项目影响与建议分别使用项目符号，每条只表达一个主题，并以“地质环境：”“灾害易发性：”“工程影响：”“实施建议：”等简短中文标签开头；主要交付文件单独列出 Excel 与 Word。各标题前后留一行空行，不把多个主题挤在同一段，不输出连续六行以上的普通段落。除文件链接所需的反引号外，不使用 `**` 或反引号制造强调。

`references/api.md` 是本技能的字段权威说明。分析前按其中的完整字段映射解释响应，不得提示“字段含义未知”“需要核实”或“待字段字典确认”。用户可见的对话、结果表、Excel 表头和 Word 正文一律使用中文字段名称；任何英文字段代码出现时必须写成“中文名称（接口字段）”，不得只显示英文缩写。不同图层分别统计；不得相加不同图层的面积，每个比例必须写明本图层的统计口径。

## 用户可见语言

- 默认以中文回答；成果文件名、报告正文、章节标题、表头、成果说明和处理提示使用中文。用户明确要求其他语言时除外。
- 脚本、命令、参数、接口字段、JSON 键名与协议标识保持原样；英文专有名词和引用原文按需保留，不强行翻译。原文对比不得翻译后再比较。
- 最终回复只列正式成果，并说明真实失败项或限制，不将内部文件作为额外交付。
