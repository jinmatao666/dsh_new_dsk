# 按渠道配置模型

[English](channel-model-configuration.md) | 中文

## 参考

模型定义列表支持全部渠道、单个来源渠道及未绑定渠道筛选。多来源模型会出现在每个匹配渠道的结果中，来源列只显示匹配来源。单模型连通性测试及“测试当前列表”会将选中渠道编号传给后端，后端在发送请求前排除其他来源。“全部渠道”下保留测试所有来源的行为。模型能力检测仍检查所有来源。

单个添加要求先选渠道，再选模型 ID。可搜索的模型菜单与输入框等宽，候选来自渠道已保存的模型清单，而不是上游获取结果。切换渠道会清空模型 ID 和显示名称。服务端创建定义前，按渠道当前配置校验提交的 `source_channel_id`。不提交该字段的既有 API 调用保留原创建行为，通用来源编辑接口保持不变。

模型页读取不分页、仅管理员可访问的渠道目录，字段为编号、名称、已配置模型和状态，不包含 API 密钥。从渠道配置切回模型配置会刷新目录。获取上游模型失败不影响选择手动配置的模型；配置清单包含某模型，并不证明上游已授权或推理一定成功。

## 批量添加

选择渠道，搜索已配置模型并主动勾选，默认不选。“全选／反选”作用于搜索匹配且可选择的条目，保留搜索范围外的选择。已有定义且已绑定当前渠道的模型不可选择。已有定义但缺少当前绑定的可选择，并标为仅补绑定。“下一步”展示逐模型显示名称、类型、上下文和计费倍率确认表；已有定义的配置只读。

每个选中模型分别提交到 `POST /api/model_definition/from_channel`。新定义、默认分组来源和两项倍率在同一数据库事务内提交。新定义默认禁用，需主动启用。倍率为零表示免费，启用前需确认。已有定义保留元数据、倍率及其他来源，只新增缺失绑定。重复已完成请求返回 `skipped`，不更新原配置。登记不执行上游获取、连通性测试或图片检测。

弹窗保留每个模型的成功、跳过和失败消息，只重试失败或结果未确认的条目。请求超时为 30 秒；超时表示结果未知，不代表已回滚，重试不会重复登记。提交期间禁止关闭和修改确认表。整个批次不是一个事务：某项失败时，其他成功项仍已提交。本次不增加路由别名或成本／速度自动调度。既有单模型编辑的保存链路及自动图片检测保持不变。

## 验证

`ChannelModelTools.test.js` 覆盖实际模型页面及批量、选择器交互。`go test ./controller -run '^TestChannelModelRegistration$' -count=1` 覆盖真实 Gin 请求与独立 SQLite 数据库；设置 `DSH_SKILL_INSTALLATION_TEST_POSTGRES_DSN` 时使用临时 PostgreSQL 模式。测试检查渠道清单归属、新模型默认禁用、安全重试、保留原配置、事务回滚、不含密钥的目录，并用本地假上游验证只测试选中渠道。测试禁止使用生产凭据。
