# 技能与专家使用统计

管理后台「使用统计」位于「模型日志」上方，包含积分统计、技能统计、专家统计、技能明细、专家明细。统计页提供 Top 10、部门汇总与按天/周/月趋势；明细页显示人员、使用时间、名称和部门。

服务启动时通过 GORM `AutoMigrate` 核对并创建 `usage_events` 表，无需手动建表。每条事件使用稳定的 `event_id` 作主键，仅对同一事件的网络重试去重；不同对话轮次、同一轮的多次模型调用均分别计数。

技能事件由桌面端登录用户令牌上报。用户消息中的技能标记记录为 `invocation_type=user_explicit`，模型发出的 `skill` 工具调用记录为 `model_auto`；管理后台将两类合并统计，原始类型保留在表中。专家网站仅在任务提交给执行器后用注册的提供方凭据上报，平台依据已核验的票据用户编号和提供方专家资料写入记录。

`department_id` 可为空，`department_name` 暂时为空；未归属人员在后台显示「未归属部门」。后续接入组织关系时，应在服务端写入事件发生时的部门快照，不接受客户端自报部门。

接口：`POST /api/usage/skill`（用户鉴权）、`POST /api/expert-web/usage`（提供方凭据）、`GET /api/usage/admin/stats` 与 `/details`（管理员鉴权）。查询日期以中国标准时间的自然日为准，最多查询一年。

## 积分统计

管理员查询 `GET /api/usage/admin/credits`：`from`、`to` 为北京时间日期，`user_id`、`actor_id` 为用户及操作人编号，`keyword` 搜索账号、姓名、手机、邮箱、单位、部门、操作人、扣分项或业务编号。支持 `source` 来源、`direction=in/out` 方向和 `page` 分页，每页 20 条。

`credit_ledgers` 保存实际余额变动，含时间、用户与单位部门快照、操作人、来源、扣分项说明、业务编号、变动额及前后余额；金额单位与 `users.quota` 相同，接口同时返回换算比例 `quota_per_credit`。个人账户记录 `user_id`，企业账户记录 `org_id`，成员调用记在 `actor_id`。

余额更新和流水写入在同一事务中，重复计费请求不重复记账。预扣、补扣、退回、发放、订阅调整、过期回收及账户转换分别记录；借助计费任务编号可追溯最终状态。减少积分包含预扣与回收，不代表最终消费。

启动后后台幂等补录已有发放、计费、模型及知识库凭证，不阻塞服务；`history_status` 标识补录状态。`audit_since` 为完整台账起点；更早的过期回收、订阅替换等未留存的变动无法还原，不将可变订阅账本冒充历史流水。旧数据没有的操作人、余额不推算，已合并的永久发放批次保留批次标识，无法还原每次原始发放时间。之后所有经本服务写入的余额变化均保留独立流水；直接手工修改数据库不会触发服务内审计。
