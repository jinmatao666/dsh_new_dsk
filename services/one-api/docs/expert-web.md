# 独立专家网页接入接口

`/api/expert-web` 与旧 `/api/expert` 并存。旧桌面工作台和旧专家资料接口不受新网页目录影响。新目录只返回已上架的独立网站；管理员登记新专家时无需在服务端增加固定专家 ID。

## 管理与发布

2026-09-28 更新：工作台登记与打开接口现在支持 HTTP 或 HTTPS，以下原有 HTTPS 要求不再是强制限制，仍建议使用 HTTPS。当前统一公网核验地址为 `http://ac.zjugis.com:3300/api/expert-web/redeem`，会议工作台为 `http://ac.zjugis.com:3301`。HTTP 会使提供方凭据、登录票据和会话数据面临明文传输风险；来源检查和一次性票据不能替代传输加密。网站核验不得跟随重定向；桌面端批准来源须包含准确的协议、域名和端口。需重建本服务镜像和桌面安装包，并重部署网站，不能只修改后台地址。

管理员使用现有 OneAPI 管理会话访问“专家管理 → 专家”。`GET /api/expert-web/admin/list` 返回全部资料，`POST /api/expert-web/admin/` 创建未上架网站，`PUT /api/expert-web/admin/:key` 修改资料，`PUT /api/expert-web/admin/:key/publish` 上下架。工作台地址必须是无用户信息、无片段的 HTTP 或 HTTPS URL。`POST /api/expert-web/admin/:key/credential` 重新生成提供方凭据，旧凭据立即失效。创建和重置响应只显示一次明文凭据，数据库只保存 SHA-256 摘要；管理员应把凭据交给该网站后端的密钥配置，不得放入网页或桌面包。

后台只有“专家”和“分类管理”两个栏目。卡片使用名称、副标题、简介和标签；点击后的弹窗还使用同一主图标、四个可编辑的 `detail_sections` 区块及独立的 `footer_note` 底部说明。后台上传 PNG、JPEG、WebP 或 GIF 后，会压缩为不超过 60 KB 的 WebP 数据并与资料一同返回，桌面端卡片和弹窗共用该图片。网站地址也由后台编辑；网页内部功能、使用说明、任务记录与成果由各专家独立网站维护。分类管理的数量使用 `web_expert_count`，只统计独立网页专家，包含未上架记录；旧 `expert_count` 和旧专家接口保留以保护已有客户端。分类重命名会同步更新两个目录的关联；仍有任一专家绑定的分类不能禁用或删除。

公开 `GET /api/expert-web/` 仅返回已上架网站的展示资料和工作台地址，不返回提供方凭据。后台操作仍受现有 `AdminAuth` 和管理员操作日志约束。上架专家意味着该网页将来可使用桌面端授权的原生能力，因此只应上架由团队实际控制并已审核的站点。

## 一次性身份交接

桌面 Host 持有 OneAPI 用户令牌，调用 `POST /api/expert-web/:key/launch`。接口使用现有 `UserAuth`，仅对已上架专家签发 90 秒票据，返回 HTTPS 工作台 URL 和一次性票据。桌面把票据放在 URL 片段中打开网站，不把用户令牌传给网站。

网站后端使用 `Authorization: Bearer <provider_credential>` 调用 `POST /api/expert-web/redeem`，JSON 请求体为 `{ "ticket": "..." }`。平台核对专家、提供方凭据、有效期和上架状态，并以数据库条件更新原子消费票据；成功时返回 `{ "user_id": "123" }`。重复使用、过期、下架或错配均失败。网站据此创建自己的会话；任务、历史与成果只由该网站保存和展示。

提供方请求必须使用完整的 `Bearer` 授权头；不接受裸凭据或其他授权类型。票据与凭据必须符合服务端生成的 64 位小写十六进制格式。

签发新票据前会按已建立索引的过期时间清理过期记录，不删除仍有效的票据。这是请求触发的清理，不是定时任务：没有新的打开请求时，过期记录可能暂时留在数据库，但不能再兑换。

`controller/expert_web_integration_test.go` 使用临时 SQLite 数据库和真实 HTTP 处理器，覆盖动态目录、凭据不泄露、过期、重放、上下架、凭据轮换及并发兑换。测试路由注入测试用户，不替代生产 `UserAuth` / `AdminAuth` 中间件验证；生产数据库为其他类型时仍需在目标数据库重复验证。客户端容器及桌面原生权限也仍需跨平台验证，不能仅凭接口通过宣布整条链路已可生产使用。
