> 历史讨论草案：统一接口以 [统一业务积分接口 v1](unified-business-billing-v1.md) 为准，下面的专家专用路径未实施，不应作为接入地址。

# 专家任务接入标准 v1（草案）

现有 /api/expert-web/:key/launch 和 /api/expert-web/redeem 继续负责打开专家和兑换一次性身份票据。打开页面不创建任务，不扣积分。以下三个接口为新增契约，尚未上线。

| 接口 | 调用方 | 用途 |
|---|---|---|
| POST /api/expert-web/:key/tasks | 专家后端 | 用户明确点击开始时创建任务 |
| POST /api/expert-web/:key/tasks/:id/result | 专家后端 | 回报任务结果 |
| GET /api/expert-web/:key/tasks/:id | 专家后端 | 查询任务和结算结果 |

所有接口仅允许 HTTPS。专家后端用该专家独立凭据认证，凭据不下发浏览器。创建任务另需平台签发、限定专家和用户、短时有效的任务授权；不能凭传入的 user_id 扣用户积分。现有打开票据不直接当扣费授权使用。

## 创建任务

请求示例：

    {"request_id":"用户本次启动的唯一编号","task_grant":"平台签发的启动授权"}

响应示例：

    {"task_id":"平台任务编号","state":"reserved","points":"2.5","expires_at":"2026-11-07T10:10:00Z"}

专家先展示单次积分；启动授权绑定用户确认时的价格版本。若确认后价格已变，返回 PRICE_CHANGED，要求重新确认。平台锁定单价、预留积分并创建任务，三者在同一事务内完成。余额不足返回 INSUFFICIENT_CREDITS，专家不得执行收费任务。同一专家和用户下重复提交同一个 request_id，返回原任务，不再预留；相同编号但不同业务意图返回冲突。0 积分任务也可以走这套接口，但不产生积分扣减。

## 回报结果

请求示例：

    {"status":"succeeded"}

状态只接受 succeeded、failed、cancelled。失败可以附约定的 reason_code，不上传提示词、回复、文件或用户原始输入。平台核对任务归属和有效期；成功则结算预留金额，失败、取消或超时则释放。专家不传扣费金额。重复提交同一结果返回现有结算状态；冲突终态返回 409，不修改流水。超时后的成功回报不得补扣。

查询接口返回任务状态、锁定价格、实际扣分、到期时间。任务结算和流水写入同一事务；回报与超时清理竞争时只能有一个终态。所有金额以十进制字符串传输，后台按现有积分精度存储。

## 后台配置和迁移

每个专家独立配置「单次积分」，默认 0；未通过 v1 接入验收的旧专家只能配置 0。改价只影响新任务。固定专家费对应一次明确启动的任务，内部步骤不重复收专家费。第一版先挑一个能明确回报结果的专家验证：正常扣分、余额不足、重试、失败释放、超时和跨专家越权。专家费与已有模型计费的叠加规则需在试点上线前确定，并在启动前告知用户。

## v1 实施约束

- **平台确认后启动**：桌面端使用登录态从平台获取报价并确认；报价包含专家 ID、单次积分及价格版本。专家页面不能自行签发授权。授权绑定本次启动编号，首次消费与创建任务在同一事务内；同一启动编号重放应先返回原任务，再检查授权是否过期。
- **独立专家身份**：专家后端请求只能操作所属专家的任务。凭据轮换应支持进行中的任务继续由该专家回报；日志不得记录凭据或授权。价格为 0 也校验身份和任务归属。
- **统一任务状态**：预留成功后为 reserved，终态为 succeeded、failed、cancelled、expired。有效期以服务端时间为准。任务、预留和结算都须持久化，服务重启后继续处理过期任务。超时扫描按批次运行，不能只在查询时释放。
- **积分账本**：预留时保存各额度来源的扣减明细，释放时按来源回退，并遵守原有效期；成功只落一条实际消费流水，包含项目类型、项目 ID、任务 ID、锁定单价、结算时间。用户余额、预留与流水不能各自独立提交。
- **统一错误码**：400 INVALID_REQUEST，401 UNAUTHENTICATED，404 TASK_NOT_FOUND（含归属不匹配），409 PRICE_CHANGED / REQUEST_CONFLICT / TERMINAL_CONFLICT，410 GRANT_EXPIRED / TASK_EXPIRED，403 INSUFFICIENT_CREDITS。重试仅使用原启动编号，不能重新生成。
- **技能计费边界**：仅统一执行入口能产生可计费任务。读取技能说明、安装、下载和模型内部工具步骤不计技能费。用户明确启动后由执行端创建任务并依据执行结果结算；禁止使用现有技能使用统计事件作为扣费凭据。
- **独立价格配置**：专家和技能分别保存自己的单次积分及版本，默认 0。配置接口校验运营版、接入就绪、积分精度和管理权限，并保留管理员改价审计。未接入的专家和指导型技能只允许 0；改价与下架不改变已启动任务的结算金额。
- **费用展示**：专家和技能的固定费分别入账。现有模型调用继续按原规则计费，若任务包含另计的模型用量，启动前明确显示。独立专家内部未接入网关的模型成本由专家固定费覆盖。
