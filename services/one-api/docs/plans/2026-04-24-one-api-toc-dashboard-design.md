# One-API TOC 数据大屏功能设计（V1）

## 1. 目标与定位

面向 TOC（消费者）业务的数据大屏，不仅展示“今天用了多少”，更要回答：

- 用户是否在增长，增长速度是否健康？
- 订单与营收是否稳定，是否有异常波动？
- 哪些“商品”卖得好，哪些在拖后腿？
- 新用户是否留存，老用户是否流失？
- 渠道/模型/活动对业务增长的贡献分别是什么？

适用场景：

- 运营日常巡检（每日看板）
- 管理层周/月复盘（经营看板）
- 活动效果评估（增长看板）

---

## 2. 结合当前 one-api 的数据现状

当前仓库已具备可直接利用的数据基础（无需大改即可做第一版）：

- 用户域：`users`（含 `quota`、`used_quota`、`request_count`、`inviter_id`）
- 使用域：`/api/user/dashboard`（按日 + 模型聚合的请求、Token、Quota 消耗）
- 交易域：`recharge_records`（充值流水）、`recharge_packages`（套餐）
- 订阅域：`subscriptions`（月付/年付、状态、周期）
- 财税域：`invoices`（开票状态、金额、时间）

说明：你提到的“商品售卖情况”在 one-api 里可先映射为“充值套餐（recharge_packages）”，后续如有实体 SKU 再扩展为通用商品维度。

---

## 3. 看板功能地图（建议模块）

## 3.1 经营总览（首页大屏）

核心 KPI 卡片（今日 / 昨日 / 近7日 / 近30日，支持环比）：

- 新增用户数、累计用户数
- 付费用户数、付费率
- 订单数、支付成功率
- GMV（总成交额）、实收金额、退款金额（如有退款）
- ARPU、ARPPU
- 请求量、Token 消耗、额度消耗

异常提示卡片：

- 指标突增/突降（阈值 + 同比/环比）
- 支付成功率下降预警
- 留存下降预警

---

## 3.2 用户增长与增长速度

图表与功能：

- 新增用户趋势（日/周/月折线）
- 净增长趋势（新增 - 流失）
- 增长速度（增长率）趋势
- 来源拆分（自然/邀请码/活动/渠道）
- 注册转化漏斗（访问 -> 注册 -> 首次付费）

关键指标：

- DAU / WAU / MAU
- 新增用户环比、同比
- 激活率（注册后 X 天内有调用行为）

---

## 3.3 订单与金额分析

图表与功能：

- 订单趋势（创建订单、支付成功订单）
- 交易金额趋势（GMV、实收）
- 客单价趋势（AOV）
- 支付方式分布（微信/支付宝/其他）
- 订单状态分布（待支付、成功、失败、关闭）

关键指标：

- 支付成功率 = 成功订单 / 创建订单
- 订单转化率 = 支付成功订单 / 下单用户数
- 复购率（周期内有 2 次及以上支付）

---

## 3.4 销量与商品分析（套餐分析）

图表与功能：

- 套餐销量排行（件数）
- 套餐销售额排行（金额）
- 套餐转化率（曝光 -> 下单 -> 支付）
- 套餐组合分析（月付 vs 年付、不同等级）
- 套餐生命周期（新增、升降级、续费、流失）

关键指标：

- 热销套餐 TopN
- 低转化套餐预警
- 年付渗透率
- 套餐升级率（低档 -> 高档）

---

## 3.5 用户留存与生命周期

图表与功能：

- 次日、7日、30日留存曲线
- Cohort 留存热力图（按注册周/月）
- 回流用户趋势（沉默后重新活跃）
- 流失用户趋势（连续 X 天无行为）
- LTV 趋势（按注册批次）

关键指标：

- D1 / D7 / D30 留存率
- 流失率、召回率
- 平均生命周期（天）
- 生命周期价值（LTV）

---

## 3.6 使用行为与产品健康（one-api特色）

图表与功能：

- 请求量、Token、Quota 消耗趋势
- 模型使用分布（按模型/分组/用户等级）
- 高价值用户用量分层（RFM 思路）
- 峰值时段热力图（小时 x 星期）
- 错误率/限流率/失败重试趋势

关键指标：

- 人均调用次数
- 人均 Token 消耗
- 请求成功率
- 模型成本占比（如可关联上游成本）

---

## 4. 大屏布局建议（主流 TOC 后台范式）

建议采用“1 页总览 + 4 页专题”的结构：

- 总览页：高层 KPI + 异常 + 关键趋势
- 增长页：新增、转化、渠道、漏斗
- 交易页：订单、金额、支付漏斗、复购
- 商品页：套餐销量、销售额、转化、结构
- 留存页：cohort、回流、流失、LTV

总览页推荐布局（16 栅格）：

- 顶部：时间筛选 + 业务筛选（渠道、套餐、用户分层）
- 第一行：8~10 个 KPI 卡片
- 第二行：用户增长趋势 + 交易金额趋势
- 第三行：套餐销售排行 + 模型使用分布
- 底部：留存曲线 + 异常事件流

---

## 5. 指标口径（先统一，再开发）

需要在文档中明确口径，避免“同指标多算法”：

- 新增用户：统计周期内首次注册成功用户
- 活跃用户：周期内至少有一次有效请求或有效支付的用户
- 付费用户：周期内支付成功金额 > 0 的用户
- GMV：支付成功订单金额总和（不扣退款）
- 实收金额：GMV - 退款金额 - 优惠抵扣（按财务口径）
- 留存率（D7）：某日新增用户中，第 7 天仍活跃用户占比
- 流失用户：连续 N 天无活跃行为

---

## 6. 数据维度与筛选器设计

全局筛选建议：

- 时间：今日/昨日/近7日/近30日/自定义
- 用户维度：新用户/老用户、付费层级、地区（如有）
- 交易维度：支付方式、订单状态
- 商品维度：套餐、账期（月付/年付）
- 使用维度：模型、分组、渠道

下钻能力（主流产品常见）：

- 从“总指标”点击进入“明细列表”
- 从“趋势异常点”跳转“异常用户/订单明细”
- 从“套餐排行”跳转“套餐详情页（转化路径 + 留存贡献）”

---

## 7. one-api 落地路线图（建议分 3 期）

## 第一期（1-2 周，快速上线可见价值）

基于已有表与接口先做经营总览：

- KPI：新增用户、请求量、Token、Quota、充值金额、订单数
- 趋势：近7日/30日曲线
- 分布：模型使用、套餐销量 TopN
- 基础留存：D1 / D7（简版）

产出：

- 管理后台新增“数据大屏”入口
- 可导出日报（CSV）

## 第二期（2-4 周，增长与交易深化）

- 漏斗（注册 -> 激活 -> 首付）
- 支付分析（成功率、方式分布、失败原因）
- 套餐结构（年付渗透、升级率、复购率）
- cohort 留存热力图

## 第三期（持续优化，智能化运营）

- 异常检测与预警（Webhook/站内通知）
- 用户分群（高价值、风险流失、价格敏感）
- 经营预测（下周营收、留存趋势）
- A/B 实验看板（活动对增长与付费的增量贡献）

---

## 8. 可选图表清单（按优先级）

P0（必做）：

- KPI 卡、折线图、柱状图、堆叠柱状图、排行榜表格

P1（建议）：

- 漏斗图、留存热力图、贡献度帕累托图、双轴趋势图

P2（增强）：

- 桑基图（流转路径）、箱线图（用户价值分布）、预测区间图

---

## 9. 权限与数据安全建议

- 管理员可看全局；运营按组织/分组可看局部
- 金额类与发票类指标设置细粒度权限
- 所有导出操作记录审计日志
- 指标查询建议加缓存与限流，避免大查询影响主业务

---

## 10. 最小可实施版本（MVP）建议

如果你希望尽快上线，MVP 推荐先做这 10 个组件：

- 6 个 KPI 卡：新增用户、活跃用户、订单数、GMV、请求量、Token
- 2 个趋势图：用户增长趋势、金额趋势
- 1 个分布图：套餐销售结构
- 1 个留存图：D1/D7 留存趋势

这套组合基本覆盖你提到的：

- 用户增长量 + 增长速度
- 订单数据 + 金额数据
- 销量 + 各商品（套餐）售卖情况
- 用户留存

并且与 one-api 现有数据模型贴合，能低成本启动。
