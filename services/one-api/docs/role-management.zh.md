# 角色管理

[English](role-management.md) | 中文

角色定义位于 OneAPI 主数据库的 `public.roles` 表，`users.role` 保存分配的编号；角色定义不在账号中心数据库中。

创建角色需要名称和 `role_type`（`member` 普通成员或 `admin` 管理员）。服务端在现有权限区间内分配空闲编号：普通成员为 2–9，管理员为 10–99。历史账号引用但没有角色定义的编号也会跳过。客户端不能指定编号或创建超级管理员。只有超级管理员能够创建、删除管理员角色。现有按编号比较的鉴权逻辑保持不变。

内置普通成员（1）、超级管理员（100）及所有标记为 `is_builtin` 的角色不可删除。`DELETE /api/role/:role` 会拒绝仍被任何账号引用的角色，包括软删除账号。删除自定义角色前需要先为用户更换角色。删除角色不修改用户账号。删除成功后同步清理前端角色缓存。

新建弹窗支持普通成员／管理员选择、自动编号、行内错误提示及请求期间禁止重复提交。删除需要单独确认。角色列表保留可用模型配置，并标明每个角色所属的权限类别。模型弹窗的“全选／反选”作用于当前目录中的全部模型，包括滚动区域外的条目；保留目录中暂未出现的已有权限，点击“保存”才生效，“取消”则丢弃修改。加载中或目录为空时禁用批量操作。

验证命令：`go test ./controller -run '^TestManagedRoleLifecycle$' -count=1`，以及前端 `RolePermissions.test.js`。Go 测试使用独立 SQLite；设置 `DSH_SKILL_INSTALLATION_TEST_POSTGRES_DSN` 时使用临时 PostgreSQL 模式，测试禁止使用生产凭据。
