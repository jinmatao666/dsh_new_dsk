# @deepseek-ai/dsh-wanwei-knowledge-base

English | [中文](README.zh.md)

The sidebar entry follows the administrator’s shared order and its environment-specific visibility setting. See [deployment policy](../oneapi-auth/README.md).

In the operations edition, a maintainer saves three per-file prices before applying to publish a subscription library. Each price is capped by the administrator’s per-file limit, shown below the corresponding label. Desktop Settings → Credits and usage → Knowledge credits edits those prices after approval. Owners can withdraw a public or subscription publication from the personal library. Withdrawal removes shared access and subscriptions while retaining the original library and its files. Paid subscription Q&A uses the knowledge page, which receives final RAGFlow citations.

## Summary

This Client plugin adds the administrator-controlled Knowledge Base entry. OneAPI owns authorization, local records and the RAGFlow credential; the browser receives only authorized knowledge-base metadata, document metadata, parsed preview text, downloadable file bytes, saved Q&A turns, answers and locatable citations.

## Use this package

Mount the plugin after `dsh-wanwei-oneapi-auth` and `dsh-wanwei-feature-panels`. Configure `RAGFLOW_BASE_URL` and `RAGFLOW_API_KEY` on the OneAPI server. Each new conversation creates an isolated RAGFlow chat assistant and session. The knowledge Q&A pane clears the caller's saved turns for the open library by replacing that RAGFlow session.

Personal knowledge bases are visible only to their owner on the desktop, including for administrators and root; the workbench catalog still lists every personal library for root. Shared knowledge bases are visible to their owner and to user or department grants stored by OneAPI. Published common libraries are visible to every signed-in user. Workbench tabs are Personal plus each created category. The desktop sidebar always shows Personal and 订阅知识库 (empty groups show 暂无知识库); 公共知识库 merges every open (non-auth) library and appears only when non-empty; 订阅知识库 lists only grant-backed subscriptions after approval (not self-built libraries). Auth category names never appear as sidebar groups. The FeaturePanel header uses staged `/knowledge-covers/hero-banner.png` via `headerArt`. Auth libraries are discovered through the sidebar's Knowledge Plaza resource card (staged `/knowledge-covers/plaza-entry.png` as the entry plate, with product copy overlaid); the plaza uses the Expert and Skill catalog visual system for its resource-center header, image-led cards, status badges, and responsive detail. Personal-library artwork, PDF glyph, and clock use staged PNG cutouts under `/knowledge-covers/`; group marks and chat toggles use SVG, and public and subscription libraries use a layered book SVG with a globe or bookmark. Saved library covers take precedence in sidebar rows and the compact selected-library header. The plaza entry uses the staged book-and-background PNG. Self-built auth libraries appear on the plaza with status 我的, sorted after other cards, with the same Q&A and file-open capability as 已订阅, and stay out of the sidebar subscription group. After workbench approval, other libraries remain on the plaza (with subscriber count) and also appear under 订阅知识库. Plaza detail is split: left keeps catalog and subscribe status, right is knowledge Q&A; approved or owned file rows open the same viewer as the content list. Opening a granted (non-owned) library offers 取消订阅; owned libraries never show that control. Uploads are limited to 20 MB. The workbench create and edit dialogs can attach, replace, or clear an optional cover image. The desktop create dialog does not show cover upload yet. Plaza cards and the plaza detail use the stored cover, and use the staged natural-resources photo when the library has none. On the create dialog, any signed-in user may either create a blank RAGFlow dataset or bind one already listed at `{RAGFLOW_BASE_URL}/api/v1/datasets` (the same origin as the RAGFlow datasets UI); datasets already linked to a local library are omitted from the picker.

The desktop page keeps Q&A closed by default so the content pane fills the width. The sidebar separates name search from Personal, Public, and Subscription groups. The three groups use low rounded trapezoid tabs in indigo, teal, and violet, with a continuous bottom rule when collapsed; expanded groups contain white library rows and a matching selection outline. The theme accent is `#0865F2`. Maintainer, update time, file count, and size use a compact two-column text layout. Each sidebar library card shows its name, up to two tags, maintainer, update time, file count, and file size. Personal entries show their owner as maintainer, including while publication is pending or rejected. In the operations edition, approved public and subscription entries show 万维. Other editions show 万维 for public and subscription entries on internet deployments and the creator on intranets. Clicking the library name or information area selects the library. The detail arrow beside its title toggles the description and, for subscription cards, subscriber count and the existing cumulative `visit_count` (authorized opens and uses). The library list scrolls above the fixed Knowledge Plaza shortcut. These details start closed and appear below the two-column maintainer, update time, file count, and file size when expanded: description first, followed by subscription statistics in the same text layout. Tags and these basic statistics remain visible. Switching libraries closes all expanded details; returning to a library does not restore them. The personal-library create form accepts comma-separated tags, stored in the workbench `tags` field. A chat icon button in the card's top-right corner opens or closes that library's Q&A pane and shows a highlighted pressed state while open; with Q&A open the file list shows one column, its pager is hidden to preserve the designed two-pane work area, and no draggable divider exists. The full-width search box above the sidebar groups filters libraries by name and expands matching groups. The content toolbar has a file-name search and a newest/oldest upload-time sort; while Q&A is closed, the list paginates by top-level folder or file (12 per page) with the design pager (`第 x 页 / y`, prev/next, numbered pages, `跳至` input) pinned under a flex scrolling file list and shown whenever the list is non-empty, including a single page; the panel body uses `bodyClassName: dsh-knowledge-host` so desktop WebViews keep the pager visible. The Knowledge Plaza homepage uses equal-size image cards with clear, unfiltered covers, white status badges and saved favorites. It paginates cards at 10 per page and shows the pager whenever the catalog is non-empty, including a single page; the pager is a flex sibling of the scrolling catalog so short hosts cannot collapse it away. Each file card shows its upload time and its creator. OneAPI records the creator when a file is uploaded or copied into a library; the creator is omitted for the caller's own files and for files uploaded before creators were recorded.

The composer tool row carries a 知识库 switch. Turning it on opens a picker that groups libraries exactly like the desktop sidebar (Personal, 公共知识库, 订阅知识库) and accepts up to 20 libraries across groups. The plugin sends the selection for the current Session to the Host with the `retrieval-scope` operation and transfers it to a Session created by a first send. Turning the switch off hides the picker and clears the Session scope, so later turns run unchanged. The switch is hidden when the deployment hides knowledge libraries on the current network.

Desktop files and folders use a responsive card grid inside a white content panel with a low trapezoid heading. Each card places an enlarged cover with a file-type border and light shadow beside its name and existing attributes. Empty personal-library folders offer a delete button with confirmation; files and child folders must be removed manually first, and the backend checks again. In the operations edition, an owned personal library has a compact Publish menu for public or subscription sharing, with no target category selection. Submission requires administrator approval. Approval sets the sharing scope on the same library and keeps its personal entry and owner editing. A public library also appears under Public; an owner-published subscription library appears under Subscription and on the plaza. Other users need subscription approval to read the latter. The government edition rejects publication requests.

## Model Experience

### Composer knowledge retrieval

#### What the model sees

When the current Session has a library scope, the `dsh-wanwei-oneapi-auth` Host plugin retrieves chunks for the user's question through OneAPI `POST /api/knowledge-bases/retrieval` (RAGFlow `POST /api/v1/retrieval`) before the first step of each user turn. It logs one `notice` user message from `wanwei-knowledge-retrieval` after the question with the numbered chunks, their file and library names, and an instruction to cite sources. An empty result or a retrieval failure is logged as a short statement instead. The Session's own model writes the answer; RAGFlow chat assistants are not involved.

#### Token effect

Each scoped user turn adds up to `knowledgeRetrievalMaxChars` characters of chunk text plus a fixed instruction. Turns without a scope add nothing.

#### KV Cache effect

The retrieval message is appended after the user message, so the prefix before the turn stays cacheable.

### Browser-owned knowledge conversation

#### What the model sees

RAGFlow receives the selected dataset, the user's question and the conversation's RAGFlow history. The Harness agent loop receives none of this content. Before CreateChat or UpdateChat, OneAPI checks whether the dataset already has retrieval chunks: still-parsing targets return `文件正在解析，请稍后重试`, and datasets with zero chunks (including DONE files that produced none) return `知识库尚无可检索内容，请等待文件解析完成后再试`, both as normal answers instead of the RAGFlow gateway error `doesn't own parsed file`. Finished answers show up to three related prompts (with a trailing question mark) and brand the assistant as 万维Buddy beside the logo.

#### Token effect

Token use belongs to the RAGFlow assistant and its configured model.

#### KV Cache effect

Each knowledge conversation owns a distinct RAGFlow assistant and session, so cache reuse does not cross conversations.

## Known Limitations and Deferred Work

- The creation dialog does not yet expose user and department grant editing; the database and API accept grant records for the administration workflow.
- Cover upload is on the workbench create and edit dialogs only. The desktop create dialog does not show it yet; the desktop still displays a stored cover on the plaza and the open library header.
- Upload starts RAGFlow parsing asynchronously on the server; the desktop page does not expose manual re-parse. Click opens a viewer. In the desktop app, the viewer saves the original file in Downloads and reports the result in the preview. Right-click on blank space in a 个人知识库 file list offers 新建文件夹 through the same current-directory dialog as the upload menu. Right-click on a 个人知识库 file selects it and offers delete only; 公共知识库 and 订阅知识库 offer no file context actions. Delete calls RAGFlow document deletion. Images use the original file blob; PDFs render with pdf.js so answer citations can highlight RAGFlow chunk boxes (quote text-layer search is the fallback). Downloads use a binary Fetch route instead of JSON byte arrays. Plain text uses downloaded bytes; other types fall back to RAGFlow chunk text. Finished answers replace `##i$$` / `#i$` / `[ID:i]` markers with blue numbered citations from those RAGFlow `reference` chunks; the page does not invent a separate source list.
- The add-content control appears only for 个人知识库. Its menu keeps 本地文件, 网页链接 (newline-separated http(s) URLs, max 10; client regex then OneAPI fetches the page and uploads HTML/PDF via `POST .../web-links`), and 录音纪要 (floating MediaRecorder panel; Client converts to mono 16 kHz WAV and POSTs `/api/desktop-knowledge-recording-minutes` so Host ASR + chat draft 逐字稿/速览/纪要, then uploads paired `录音纪要_….md` + `.wav`; OneAPI skips RAGFlow parse for audio). Opening either sibling uses the dual-pane minutes viewer with playback. 公共知识库 and 订阅知识库 hide the upload control. 本地文件夹 selects a directory and uploads its files with relative paths. The directory aligns folder and document cards to the same grid. Each document card combines its thumbnail, filename, type or parsing progress, and upload time when available. The total file count appears beside 内容 in the toolbar. Clicking a folder shows only that directory, with breadcrumbs and a parent action to return. Uploads use the current directory, including relative subdirectories from local-folder picks. 新建文件夹 saves an empty folder under the current directory in OneAPI; empty folders remain visible after refresh and merge with uploaded paths of the same name. Folder paths are unique within each library; empty or dot segments, backslashes, control characters, segments longer than 128 characters, and paths longer than 512 bytes are rejected. Notes, Tencent docs, and personal-library import entries stay hidden.

Plaza card and detail hearts save each authenticated viewer’s preference in OneAPI. Refreshing or signing in again restores it; liking does not grant library access.

For local source updates, run `powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\wbuddu\scripts\start-wanwei.ps1 -Refresh`, then reload the desktop with Ctrl+F5. Refresh compiles the knowledge/auth TypeScript programs, bundles their clients, builds OneAPI and restarts the backend and desktop; the default invocation reuses existing services. Both modes restore product Web artwork into `apps/web/dist` before checking services, so local startup repairs images missing after an official Web rebuild.
